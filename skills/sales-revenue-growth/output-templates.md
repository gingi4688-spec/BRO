# Sales, Revenue, and Growth output templates

## English

Three domain-shaped deliverables. Fill the real fields; keep every number traceable to the user's own data, a labeled assumption, or a formula. Do not invent conversion rates, CAC, or benchmarks.

### Template 1 — Funnel / forecast model

- **Segment & period:** (channel / cohort this models, and the time window)
- **Stages (volume × conversion):**
  - Leads / MQL: ___
  - → SQL: ___% → ___
  - → Opportunity: ___% → ___
  - → Win: ___% → ___
- **ACV:** $___  →  **Bookings:** `wins × ACV` = $___
- **Target & gap:** target $___ ; gap $___
- **Sensitivity (same effort per lever):** lead volume +__% → $___ · binding-stage conversion +__pts → $___ · win rate +__pts → $___
- **Binding stage & recommendation:** (the stage with the most revenue leverage, and where effort goes)
- **Capacity & cohort check:** can the team work the pipeline? do these leads retain?
- **Assumptions / unknowns:** (rates are the user's, not benchmarks; segment before trusting the blend)
- **Acceptance:** stage math shown and correct · segmented · binding stage identified · no invented benchmarks
- **Next verification step:** (e.g. split by channel and re-run sensitivity)

### Template 2 — MEDDICC deal review

- **Deal & ACV:** account, $___, target close
- **Metrics:** quantified value (hours/revenue), or "unknown — qualify"
- **Economic buyer:** named & met? (the biggest single risk if not)
- **Decision criteria:** the buyer's stated criteria
- **Decision process:** path to signature (legal / security / procurement / budget cycle) and the close date it implies
- **Identified pain & critical event:** urgent pain tied to an event that creates a deadline
- **Champion:** influence + access, and is the deal multi-threaded beyond them?
- **Competition:** alternatives, including "do nothing"
- **Forecast call:** commit / best-case / downgrade — justified by the hard signals, not enthusiasm
- **Next step (not a number):** the specific action to close the binding gap (e.g. economic-buyer intro)
- **Acceptance:** economic buyer + decision process present for commit · evidence-backed · multi-threaded · re-score gate after the meeting

### Template 3 — Pricing / packaging memo

- **Today's price & problem:** current model and what it fails to do (e.g. no value metric, no expansion path)
- **Value metric:** the unit charged by, and why it scales with delivered value (seats / usage / outcome)
- **Packaging (tiers fenced by value):** Good / Better / Best — what value each unlocks (not random feature hostage-taking)
- **Willingness-to-pay evidence:** interviews / test / labeled assumption to validate
- **Expansion path:** how an account naturally grows its spend as it gets more value
- **Bill-shock guard (if usage-based):** caps / alerts / committed-use floor
- **Discount policy:** floor, and what each discount trades for (term / prepay / reference / scope)
- **Finance reconciliation (route out):** gross margin per tier, LTV on gross margin, CAC payback → `finance-unit-economics` before commit
- **Acceptance:** price tied to a value metric · tiers fence by value · WTP labeled · economics reconciled with finance
- **Next verification step:** (e.g. run on one segment, measure NRR vs current cohort)

## Հայերեն

Երեք domain-ձև deliverable։ Լրացրու իրական field-երը. ամեն թիվ պահիր հետագծելի user-ի սեփական data-ի, label արված assumption-ի կամ formula-ի։ Մի՛ հորինիր conversion rate, CAC կամ benchmark։

### Template 1 — Funnel / forecast model

- **Segment & period․** (որ channel / cohort է սա model անում, և ժամանակի window-ը)
- **Stage-եր (volume × conversion)․**
  - Leads / MQL․ ___
  - → SQL․ ___% → ___
  - → Opportunity․ ___% → ___
  - → Win․ ___% → ___
- **ACV․** $___  →  **Bookings․** `wins × ACV` = $___
- **Target & gap․** target $___ . gap $___
- **Sensitivity (նույն effort ամեն լծակի)․** lead volume +__% → $___ · binding-stage conversion +__pt → $___ · win rate +__pt → $___
- **Binding stage & recommendation․** (ամենաշատ revenue leverage ունեցող stage-ը, և ուր է գնում effort-ը)
- **Capacity & cohort check․** թիմը կարո՞ղ է pipeline-ը մշակել. այս lead-երը retain անո՞ւմ են
- **Assumption-ներ / unknown-ներ․** (rate-երը user-ինն են, ոչ benchmark. segment արա նախքան blend-ին վստահելը)
- **Acceptance․** stage math-ը ցույց տրված և ճիշտ · segment արված · binding stage-ը նշված · ոչ մի հորինված benchmark
- **Հաջորդ verification step․** (օր.՝ բաժանիր channel-ով և վերագործարկիր sensitivity-ն)

### Template 2 — MEDDICC deal review

- **Deal & ACV․** account, $___, target close
- **Metrics․** քանակացված value (ժամ/revenue), կամ «անհայտ — qualify արա»
- **Economic buyer․** անվանված և հանդիպա՞ծ (ամենամեծ ռիսկը, եթե ոչ)
- **Decision criteria․** գնորդի նշված criteria-ները
- **Decision process․** ստորագրության path-ը (legal / security / procurement / budget cycle) և դրա ենթադրած close date-ը
- **Identified pain & critical event․** urgent pain՝ կապված event-ի, որ deadline է ստեղծում
- **Champion․** influence + access, և deal-ը multi-threaded է՞ նրանից այն կողմ
- **Competition․** այլընտրանքներ, ներառյալ «ոչինչ չանել»
- **Forecast call․** commit / best-case / downgrade — արդարացված hard signal-ներով, ոչ ոգևորությամբ
- **Հաջորդ քայլ (ոչ թիվ)․** binding gap-ը փակելու կոնկրետ գործողություն (օր.՝ economic-buyer-ի ներկայացում)
- **Acceptance․** economic buyer + decision process կա commit-ի համար · evidence-backed · multi-threaded · re-score gate հանդիպումից հետո

### Template 3 — Pricing / packaging memo

- **Այսօրվա գին & խնդիր․** ընթացիկ model-ը և ինչ չի կարողանում անել (օր.՝ ոչ value metric, ոչ expansion path)
- **Value metric․** այն միավորը, որով գանձում ես, և ինչու է scale անում delivered value-ի հետ (seat / usage / outcome)
- **Packaging (tier-եր fenced value-ով)․** Good / Better / Best — ինչ value է ամենը unlock անում (ոչ random feature պատանդ)
- **Willingness-to-pay evidence․** հարցազրույց / test / label արված assumption՝ validate անելու
- **Expansion path․** ինչպես է account-ը բնականորեն աճեցնում իր spend-ը, երբ ավելի շատ value է ստանում
- **Bill-shock guard (եթե usage-based)․** cap / alert / committed-use floor
- **Discount policy․** floor, և ինչի դիմաց է ամեն discount փոխանակվում (term / prepay / reference / scope)
- **Finance reconciliation (route out)․** gross margin ըստ tier-ի, LTV gross margin-ի վրա, CAC payback → `finance-unit-economics` նախքան commit-ը
- **Acceptance․** գինը կապված value metric-ին · tier-երը fence են value-ով · WTP-ն label արված · economics-ը հաշտեցված finance-ի հետ
- **Հաջորդ verification step․** (օր.՝ գործարկիր մեկ segment-ի վրա, չափիր NRR-ը ընթացիկ cohort-ի դեմ)
