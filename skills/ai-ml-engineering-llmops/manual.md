# AI, ML Engineering, and LLMOps manual

## English

### Operating principle

Senior AI, ML, and LLMOps work is decision-grade only when it converts a model from a demo into a measured system, and pairs every claim with an auditable mechanism. The deliverable is usually one of a few shapes: a RAG/retrieval design, an adaptation-choice memo (prompt vs RAG vs tools vs LoRA/QLoRA vs full fine-tune), an evaluation harness, a quantization/serving plan, or an LLM/agent release checklist — and, in classical-ML work, a modeling plan with a defensible split and baseline. The single guardrail that governs all of them is the same: a recommendation is only as good as the evidence that it works and keeps working. So the first move is always to name the decision, choose the smallest learning mechanism that fits it, and define how you will know it is right before you build the generator or push the model. Two facts shape everything downstream. First, retrieval quality is decided before generation: a generator cannot cite what retrieval never returned, so the recall gate comes first. Second, volatile facts are never asserted from memory — a model id, context window, price, or benchmark is a dated verify-before-use snapshot or a placeholder, because inventing one quietly corrupts an architecture or a budget. Reliability here is not a good demo; it is a measured, sliced, monitored system with a rollback.

### Mechanism reference

- **RAG pipeline** — retrieval quality is decided before generation: normalize documents, preserve section titles, chunk by semantic boundaries, attach owner/effective-date/language metadata, retrieve broadly, rerank narrowly, then pack context with citations. A practical starting point is chunks around 300–800 tokens with 10–20% overlap; retrieve top 20 for recall and rerank to top 5 for answer context. Gate on recall@5 for the golden set and block launch when the correct source is absent, because a generator cannot cite what retrieval did not bring.
- **Fine-tuning, LoRA, and QLoRA** — tune behavior, format, and stable task patterns; retrieve changing facts. LoRA adds low-rank A·B adapter deltas to selected projection matrices instead of updating every base weight; rank 8–64 is common enough to test before full tuning, and adapters can be merged for simple serving or kept separate for tenant/task routing. QLoRA freezes a 4-bit NF4 base and trains adapters, often cutting VRAM roughly 3–4×, but it still needs license review, representative data, and slice eval.
- **Quantization and serving** — weight-only methods such as GPTQ/AWQ shrink weights; weight+activation approaches such as int8 SmoothQuant also manage activation ranges with calibration. Int4 can fall off a quality cliff when the calibration set misses long prompts, code, Armenian, or rare tool traces, so replay the exact evaluation suite after quantization. KV-cache stores per-layer key/value tensors for prior tokens; memory grows roughly linearly with context length, mitigated by paged attention, prefix caching, batching discipline, and MQA/GQA models.
- **Evaluation and drift** — combine golden examples, adversarial prompts, rubric judging, human labels, and production telemetry. LLM-as-judge is useful only after calibration against human labels because it can prefer verbose answers, earlier-listed options, or its own style. Release gates should include slice pass rates, retrieval recall, refusal correctness, latency, cost, canary rollback signal, and a dated owner for refreshing the eval set.
- **Classical-ML modeling** — fix the split before touching the data: train/val/test, and use grouped or temporal splits when rows are correlated by entity or time. Beat a trivial baseline (majority class, last value, simple heuristic) before any model earns its complexity. Hunt leakage: any feature available only after the prediction moment, or any val/test row that shares an entity with train, inflates offline scores and fails in production. When a probability drives a threshold or expected-value decision, check calibration (reliability curve, Brier score), not just ranking (AUC). Monitor for drift — feature drift and label/concept drift — and tie a refresh trigger to it.
- **Multimodal** — image, audio, and document inputs each carry their own preprocessing, token/length budget, and failure modes (OCR errors, resolution loss, audio noise, layout parsing). State the modality contract (what is accepted, how it is encoded, the size cap) and evaluate each modality on its own slice; an aggregate that hides a vision or audio slice is not a pass. Cost and latency are dominated by the heaviest modality, so size serving against it.

### Decision rules

1. Facts that change (policy, price, inventory, per-tenant) belong in RAG or a tool, not in fine-tuned weights; fine-tune only stable behavior, format, and tone.
2. Define the golden set and the recall@k launch gate before evaluating the generator; block launch when the correct source is absent from the reranked top-k.
3. Chunk on semantic boundaries (~300–800 tokens, 10–20% overlap) with section/heading awareness; never chunk by raw character count alone.
4. On hard/ambiguous queries, retrieve broadly (top ~20) then rerank to a small context (top ~5); single-stage embedding search misses the right doc.
5. Treat all retrieved/tool/pasted text as untrusted data, never instructions; gate high-privilege actions behind confirmation to stop indirect prompt injection.
6. Slice every eval (task, language, freshness, refusal boundary, safety); one severe slice regression vetoes a green aggregate, with per-slice threshold, count, and owner.
7. Calibrate an LLM judge against human labels on a sample before trusting its scores; never gate a release on judge score alone.
8. Replay the exact eval suite after quantization; a size/latency win with no quality replay is unverified, especially on long prompts, code, and Armenian.
9. For classical-ML, fix train/val/test (grouped/temporal where correlated) and beat a baseline before modeling; treat a "too good" metric as a leakage signal.
10. When a probability drives a decision, check calibration (reliability/Brier), not just ranking; a well-ranking model can be badly miscalibrated.
11. Assert feature/tokenizer/normalization parity between training and serving; pin one code path or a feature store to prevent training-serving skew.
12. Cap synthetic data and always evaluate on a real, untouched holdout; an overdose collapses diversity and trains on the model's own artifacts.
13. State a modality contract and slice-eval each modality for multimodal inputs; size serving against the heaviest modality.
14. Never assert a model id, context window, price, or benchmark from memory; use a dated verify-before-use snapshot, a formula, or a placeholder.
15. Gate the work on the running system — canary slices, refusal correctness, latency, cost, drift monitor — not on a green notebook eval, before declaring done.

### Failure-repair playbook

1. **Plan fine-tunes on changing facts** → move those facts into retrieval or a tool; keep fine-tuning for stable behavior/format, and state the recall@k gate the RAG path now needs.
2. **Chunks split mid-idea, recall is low** → re-chunk on section/heading boundaries with overlap, re-measure recall@k on the golden set, and only then look at the generator.
3. **Single-stage retrieval misses on hard queries** → add a reranker (retrieve top ~20 → rerank top ~5), measure recall before and after, and fix the earliest failing stage (recall vs rerank vs synthesis), not the model.
4. **Untrusted context is obeyed as instructions** → isolate retrieved/tool text as data, strip/escape instruction-like content, and gate any high-privilege action behind explicit confirmation; treat a successful injection as a reportable incident.
5. **Prefix/KV cache never hits or is poisoned** → move volatile/user/timestamp content after the cacheable prefix, key the cache only on trusted content, and never share a cache across trust boundaries.
6. **Release gated on judge score alone** → calibrate the judge against human labels on a sample, report the agreement, and keep the judge off the bias it shares (verbosity, position, self-style).
7. **Training set is mostly synthetic** → cap the synthetic share, restore real examples, add a diversity check, and always evaluate on a real untouched holdout.
8. **Offline metric is "too good"** → hunt leakage: drop post-outcome features, switch to grouped/temporal split, confirm no entity spans train and test, and re-measure against a baseline.
9. **Served model underperforms its eval** → assert feature/tokenizer/normalization parity, pin one code path or a feature store, and replay the serving path in eval to close training-serving skew.
10. **Aggregate is green but risk is unclear** → build slices (safety, freshness, language, refusal), set per-slice thresholds and owners, and let one severe slice regression veto the launch.
11. **Quantized model shipped on the size win** → replay the exact eval suite post-quantization, check the int4/int8 cliff on long prompts/code/Armenian, and keep a fallback to the higher-precision model.
12. **A volatile fact (model id/window/price/benchmark) is asserted** → strip the asserted number, replace with a dated verify-before-use snapshot or a placeholder/formula, and flag that a wrong value would change the architecture or budget.

### Classical-ML discipline (split, leakage, baseline, calibration, drift)

This is the non-LLM core, and most ML failures live here. Fix the **split before you touch the data**: train/val/test, with **grouped** splits when rows share an entity (user, device, patient) and **temporal** splits when the task predicts the future — a random split on grouped or time-ordered data leaks. Establish a **baseline** (majority class, last observed value, a simple rule) so a model's complexity has to earn its place; a model that cannot beat the baseline is not a result. Hunt **leakage** relentlessly: a feature computed after the outcome, an id that encodes order, or a normalization fit on the full dataset all let information from the future or the label reach the model — the tell is a metric that is suspiciously good. When a probability drives a decision (a threshold, a triage cutoff, expected value), check **calibration** (reliability curve, Brier score), not only ranking (AUC); a model can rank well and still report 0.9 when the true rate is 0.6. Finally, monitor **drift** — feature drift (input distribution moves) and concept/label drift (the relationship moves) — and tie a retrain/refresh trigger to it, because a model that was right at launch silently rots.

### Eval harness discipline: golden, adversarial, slice, judge, telemetry

A real harness has five layers. **Golden** examples lock known-correct behavior. **Adversarial** prompts probe the failure boundary (stale facts, injection, refusal cases). **Slices** decompose the aggregate by task, language, freshness, ambiguity, and safety, each with a threshold, a sample count, and an owner, so one regression cannot hide inside the mean. **Judge calibration** compares any LLM-as-judge score to human labels on a sample before the judge is trusted, because the judge shares the model's biases. **Telemetry** watches the live system (recall, refusal correctness, latency, cost, drift) so offline green is checked against production behavior. The release gate is the conjunction of all five plus a rollback threshold and a dated owner for refreshing the set — not a single headline number.

### Factual-hygiene gate: verify volatile facts or omit them

Model identifiers, context-window sizes, prices, and benchmark numbers change frequently and are easy to misremember. Never assert one from memory. Each is a **dated verify-before-use snapshot** (state the value, its source, and the date checked), a **formula/placeholder** the user fills in, or it is omitted. Inventing a value is not a small slip: a wrong context window changes a chunking and packing design, and a wrong price changes a serving-vs-fine-tune budget. Treat an asserted-from-memory volatile fact as a hard failure in review, the same as a leaked split or an unguarded injection path.

## Հայերեն

### Գործառնական սկզբունք

Ավագ AI, ML և LLMOps աշխատանքը decision-grade է միայն այն ժամանակ, երբ model-ը demo-ից վերածում է չափված համակարգի և ամեն պնդում զուգում է auditable mechanism-ի հետ։ Deliverable-ը սովորաբար մի քանի ձևից մեկն է՝ RAG/retrieval design, adaptation-choice memo (prompt ընդդեմ RAG-ի ընդդեմ tool-ի ընդդեմ LoRA/QLoRA-ի ընդդեմ full fine-tune-ի), evaluation harness, quantization/serving plan կամ LLM/agent release checklist — իսկ classical-ML աշխատանքում՝ modeling plan՝ պաշտպանելի split-ով և baseline-ով։ Բոլորը կառավարող միակ guardrail-ը նույնն է․ առաջարկն այնքան լավն է, որքան այն ապացույցը, որ այն աշխատում է և շարունակում է աշխատել։ Ուստի առաջին քայլը միշտ որոշումն անվանելն է, դրան համապատասխան ամենափոքր ուսուցման մեխանիզմն ընտրելն է, և սահմանելը, թե ինչպես ես իմանալու, որ այն ճիշտ է՝ նախքան generator-ը կառուցելը կամ model-ը push անելը։ Երկու փաստ ձևավորում են մնացած ամեն ինչը։ Առաջին՝ retrieval-ի որակը որոշվում է generation-ից առաջ. generator-ը չի կարող cite անել, ինչ retrieval-ը երբեք չի վերադարձրել, ուստի recall gate-ն առաջինն է։ Երկրորդ՝ volatile fact-երը երբեք չեն պնդվում հիշողությունից — model id-ն, context window-ը, price-ը կամ benchmark-ը dated verify-before-use snapshot է կամ placeholder, որովհետև մեկը հորինելը լուռ փչացնում է architecture-ը կամ budget-ը։ Հուսալիությունն այստեղ լավ demo չէ. այն չափված, sliced, monitored համակարգ է՝ rollback-ով։

### Մեխանիզմների տեղեկագիր

- **RAG pipeline** — retrieval-ի որակը որոշվում է generation-ից առաջ․ document-ները normalize արա, պահպանիր section title-ները, chunk արա semantic boundary-ներով, կցիր owner/effective-date/language metadata, լայն retrieve արա, նեղ rerank արա և context-ը փաթեթավորիր citation-ներով։ Գործնական մեկնակետ է մոտ 300–800 token chunk-ը 10–20% overlap-ով․ recall-ի համար վերցրու top 20, հետո rerank արա top 5-ի answer context-ի համար։ Golden set-ի վրա gate արա recall@5-ով և block արա launch-ը, եթե ճիշտ source-ը retrieval-ը չի բերել, որովհետև generator-ը չի կարող cite անել, ինչ retrieval-ը չի բերել։
- **Fine-tuning, LoRA և QLoRA** — fine-tuning-ը օգտագործիր կայուն վարքագիծ, ձևաչափ և կրկնվող task pattern սովորեցնելու համար, ոչ թե հաճախ փոխվող փաստեր պահելու։ LoRA-ն selected projection matrix-ների վրա ավելացնում է low-rank A·B adapter deltas՝ առանց base weight-երի ամբողջական update-ի․ rank 8–64 միջակայքը սովորաբար արժե փորձել նախքան full tuning-ը։ Adapter-ները կարելի է merge անել պարզ serving-ի համար կամ պահել առանձին tenant/task routing-ի համար։ QLoRA-ն սառեցնում է 4-bit NF4 base-ը և train է անում adapter-ները՝ հաճախ VRAM-ը կրճատելով մոտ 3–4×, բայց պահանջում է license review, representative data և slice eval։
- **Quantization և serving** — GPTQ/AWQ-ի նման weight-only մեթոդները փոքրացնում են weight-երը, իսկ int8 SmoothQuant-ի նման weight+activation մոտեցումները calibration-ով կառավարում են activation range-երը։ Int4-ը կարող է որակի կտրուկ անկում տալ, եթե calibration set-ը չի պարունակում երկար prompt-եր, code, հայերեն կամ հազվադեպ tool trace-եր, դրա համար quantization-ից հետո նույն eval suite-ը replay արա։ KV-cache-ը պահում է նախորդ token-ների per-layer key/value tensor-ները, ու հիշողությունը աճում է context length-ի հետ մոտավորապես գծային․ մեղմացնող միջոցներն են paged attention, prefix caching, batching discipline և MQA/GQA model-ներ։
- **Evaluation և drift** — միացրու golden example-ներ, adversarial prompt-եր, rubric judging, human labels և production telemetry։ LLM-as-judge-ը օգտակար է միայն human label-ներով calibration-ից հետո, որովհետև կարող է նախընտրել երկար պատասխան, առաջինը նշված տարբերակ կամ իր սեփական ոճը։ Release gate-ը պետք է ունենա slice pass rate-եր, retrieval recall, refusal correctness, latency, cost, canary rollback signal և eval set-ը թարմացնող dated owner։
- **Classical-ML modeling** — ֆիքսիր split-ը մինչ data-ին դիպչելը՝ train/val/test, և օգտագործիր grouped կամ temporal split, երբ row-երը correlated են ըստ entity-ի կամ time-ի։ Հաղթիր trivial baseline-ին (majority class, last value, պարզ heuristic) նախքան որևէ model-ը արդարացնի իր բարդությունը։ Որսա leakage-ը․ ցանկացած feature, որ հասանելի է միայն prediction moment-ից հետո, կամ ցանկացած val/test row, որ entity կիսում է train-ի հետ, ուռճացնում է offline score-ը և fail է անում production-ում։ Երբ probability-ն driving է threshold կամ expected-value որոշում, ստուգիր calibration-ը (reliability curve, Brier score), ոչ միայն ranking-ը (AUC)։ Monitor արա drift-ը — feature drift և label/concept drift — և կապիր refresh trigger դրան։
- **Multimodal** — image, audio և document input-ները ամեն մեկը կրում է իր preprocessing-ը, token/length budget-ը և failure mode-ը (OCR error, resolution loss, audio noise, layout parsing)։ Նշիր modality contract-ը (ինչ է ընդունվում, ինչպես է encode-վում, size cap-ը) և eval արա ամեն modality իր slice-ի վրա. aggregate, որ թաքցնում է vision կամ audio slice, pass չէ։ Cost-ն ու latency-ն գերակշռում է ամենածանր modality-ն, ուստի serving-ը size արա դրա դեմ։

### Որոշման կանոններ

1. Փոփոխվող փաստերը (policy, price, inventory, per-tenant) պատկանում են RAG-ին կամ tool-ին, ոչ fine-tune-ված weight-ին. fine-tune արա միայն կայուն behavior, format և tone։
2. Սահմանիր golden set-ը և recall@k launch gate-ը նախքան generator-ը գնահատելը. block արա launch-ը, երբ ճիշտ source-ը բացակայում է reranked top-k-ից։
3. Chunk արա semantic boundary-ով (~300–800 token, 10–20% overlap)՝ section/heading awareness-ով. երբեք raw character count-ով մենակ մի՛ chunk արա։
4. Դժվար/ambiguous query-ի վրա retrieve արա լայն (top ~20), հետո rerank արա փոքր context-ի (top ~5). single-stage embedding search-ը բաց է թողնում ճիշտ doc-ը։
5. Ամեն retrieved/tool/pasted text համարիր անվստահելի data, երբեք instruction. high-privilege action-ները gate արա confirmation-ի հետևում՝ indirect prompt injection-ը կանգնեցնելու համար։
6. Slice արա ամեն eval (task, language, freshness, refusal boundary, safety). մեկ ծանր slice regression veto է անում green aggregate-ը՝ per-slice threshold, count և owner-ով։
7. Calibrate արա LLM judge-ը human label-ի դեմ sample-ի վրա մինչ նրա score-ին վստահելը. երբեք release մի՛ gate արա միայն judge score-ով։
8. Replay արա ճշգրիտ eval suite-ը quantization-ից հետո. size/latency-ի շահ առանց quality replay-ի unverified է, հատկապես երկար prompt-ի, code-ի և հայերենի վրա։
9. Classical-ML-ի համար ֆիքսիր train/val/test-ը (grouped/temporal՝ որտեղ correlated) և հաղթիր baseline-ին նախքան modeling. «չափազանց լավ» metric-ը համարիր leakage signal։
10. Երբ probability-ն driving է որոշում, ստուգիր calibration-ը (reliability/Brier), ոչ միայն ranking. լավ rank-ող model-ը կարող է վատ calibrate-ված լինել։
11. Assert արա feature/tokenizer/normalization parity-ն training-ի և serving-ի միջև. pin արա մեկ code path կամ feature store՝ training-serving skew-ը կանխելու համար։
12. Cap արա synthetic data-ն և միշտ գնահատիր real, անձեռնմխելի holdout-ի վրա. overdose-ը կազմալուծում է diversity-ն և train է անում model-ի սեփական artifact-ների վրա։
13. Նշիր modality contract և slice-eval արա ամեն modality multimodal input-ի համար. serving-ը size արա ամենածանր modality-ի դեմ։
14. Երբեք մի՛ պնդիր model id, context window, price կամ benchmark հիշողությունից. օգտագործիր dated verify-before-use snapshot, formula կամ placeholder։
15. Gate արա աշխատանքը running system-ի վրա — canary slice, refusal correctness, latency, cost, drift monitor — ոչ green notebook eval-ի, մինչ done ասելը։

### Վերականգնման խաղագիրք

1. **Plan-ը fine-tune է անում փոփոխվող փաստեր** → այդ փաստերը տեղափոխիր retrieval կամ tool. fine-tuning-ը պահիր կայուն behavior/format-ի համար, և նշիր recall@k gate-ը, որ RAG path-ին այժմ պետք է։
2. **Chunk-երը կիսում են միտքը, recall-ը ցածր է** → re-chunk արա section/heading boundary-ով՝ overlap-ով, re-measure արա recall@k golden set-ի վրա, և միայն հետո նայիր generator-ին։
3. **Single-stage retrieval-ը բաց է թողնում դժվար query-ի վրա** → ավելացրու reranker (retrieve top ~20 → rerank top ~5), measure արա recall-ը before/after, և շտկիր ամենավաղ failing stage-ը (recall ընդդեմ rerank ընդդեմ synthesis), ոչ model-ը։
4. **Անվստահելի context-ին հնազանդվում են որպես instruction** → մեկուսացրու retrieved/tool text-ը որպես data, strip/escape արա instruction-like content-ը, և ցանկացած high-privilege action gate արա հստակ confirmation-ի հետևում. հաջողված injection-ը համարիր reportable incident։
5. **Prefix/KV cache-ը երբեք hit չի անում կամ poisoned է** → volatile/user/timestamp content-ը տեղափոխիր cacheable prefix-ից հետո, cache-ը key արա միայն trusted content-ով, և երբեք cache մի՛ կիսիր trust boundary-ի վրայով։
6. **Release-ը gate-ված է միայն judge score-ով** → calibrate արա judge-ը human label-ի դեմ sample-ի վրա, report արա agreement-ը, և պահիր judge-ը այն bias-ից, որ կիսում է (verbosity, position, self-style)։
7. **Training set-ը հիմնականում synthetic է** → cap արա synthetic մասը, վերականգնիր real example-ները, ավելացրու diversity check, և միշտ գնահատիր real անձեռնմխելի holdout-ի վրա։
8. **Offline metric-ը «չափազանց լավ» է** → որսա leakage. drop արա post-outcome feature-ները, անցիր grouped/temporal split-ի, հաստատիր, որ ոչ մի entity չի ընկնում և՛ train, և՛ test, և re-measure արա baseline-ի դեմ։
9. **Serve-ված model-ը թերակատարում է իր eval-ին** → assert արա feature/tokenizer/normalization parity, pin արա մեկ code path կամ feature store, և replay արա serving path-ը eval-ում՝ training-serving skew-ը փակելու համար։
10. **Aggregate-ը green է, բայց ռիսկը պարզ չէ** → կառուցիր slice-եր (safety, freshness, language, refusal), սահմանիր per-slice threshold և owner, և թող մեկ ծանր slice regression veto անի launch-ը։
11. **Quantize-ված model-ը ship-ված է size-ի շահով** → replay արա ճշգրիտ eval suite-ը post-quantization, ստուգիր int4/int8 cliff-ը երկար prompt/code/հայերեն-ի վրա, և պահիր fallback դեպի ավելի բարձր precision-ի model։
12. **Volatile fact (model id/window/price/benchmark) պնդված է** → strip արա պնդված թիվը, փոխարինիր dated verify-before-use snapshot-ով կամ placeholder/formula-ով, և flag արա, որ սխալ արժեքը կփոխեր architecture-ը կամ budget-ը։

### Classical-ML կարգապահություն (split, leakage, baseline, calibration, drift)

Սա ոչ-LLM միջուկն է, և ML-ի ձախողումների մեծ մասը այստեղ է ապրում։ Ֆիքսիր **split-ը մինչ data-ին դիպչելը**․ train/val/test, **grouped** split-ով, երբ row-երը entity են կիսում (user, device, patient), և **temporal** split-ով, երբ task-ը ապագան է կանխատեսում — random split grouped կամ time-ordered data-ի վրա leak է անում։ Հաստատիր **baseline** (majority class, last observed value, պարզ rule), որ model-ի բարդությունը ստիպված լինի արդարացնել իր տեղը. model, որ չի կարող baseline-ին հաղթել, արդյունք չէ։ Որսա **leakage**-ը անդադար. feature, որ հաշվված է outcome-ից հետո, id, որ կոդավորում է order-ը, կամ normalization, որ fit է ամբողջ dataset-ի վրա, թույլ են տալիս ապագայից կամ label-ից տեղեկություն հասնել model-ին — tell-ը կասկածելիորեն լավ metric է։ Երբ probability-ն driving է որոշում (threshold, triage cutoff, expected value), ստուգիր **calibration**-ը (reliability curve, Brier score), ոչ միայն ranking-ը (AUC). model-ը կարող է լավ rank անել և միևնույն է report անել 0.9, երբ իրական rate-ը 0.6 է։ Վերջում monitor արա **drift**-ը — feature drift (input distribution-ը շարժվում է) և concept/label drift (հարաբերությունը շարժվում է) — և կապիր retrain/refresh trigger դրան, որովհետև model, որ launch-ին ճիշտ էր, լուռ փտում է։

### Eval harness-ի կարգապահություն․ golden, adversarial, slice, judge, telemetry

Իրական harness-ը հինգ շերտ ունի։ **Golden** example-ները կողպում են հայտնի-ճիշտ behavior-ը։ **Adversarial** prompt-երը probe են անում failure boundary-ն (stale fact, injection, refusal case)։ **Slice**-երը aggregate-ը բաժանում են ըստ task-ի, language-ի, freshness-ի, ambiguity-ի և safety-ի, ամեն մեկը threshold-ով, sample count-ով և owner-ով, որ մեկ regression չթաքնվի mean-ի մեջ։ **Judge calibration**-ը ցանկացած LLM-as-judge score համեմատում է human label-ի հետ sample-ի վրա մինչ judge-ին վստահելը, որովհետև judge-ը կիսում է model-ի bias-երը։ **Telemetry**-ն դիտում է live system-ը (recall, refusal correctness, latency, cost, drift), որ offline green-ը ստուգվի production behavior-ի դեմ։ Release gate-ը հնգի conjunction-ն է plus rollback threshold և dated owner՝ set-ը թարմացնելու, ոչ թե մեկ headline թիվ։

### Factual-hygiene gate․ ստուգիր volatile fact-երը կամ բաց թող

Model identifier-ները, context-window չափերը, price-երը և benchmark թվերը հաճախ են փոխվում և հեշտ է սխալ հիշել։ Երբեք մեկը մի՛ պնդիր հիշողությունից։ Ամեն մեկը **dated verify-before-use snapshot** է (նշիր արժեքը, source-ը և ստուգման ամսաթիվը), **formula/placeholder**, որ user-ը լրացնում է, կամ բաց է թողնվում։ Արժեք հորինելը փոքր վրիպում չէ. սխալ context window-ը փոխում է chunking-ի և packing-ի design-ը, իսկ սխալ price-ը՝ serving-ընդդեմ-fine-tune budget-ը։ Հիշողությունից-պնդված volatile fact-ը review-ում համարիր հարդ failure, ինչպես leak-ված split-ը կամ unguarded injection path-ը։
