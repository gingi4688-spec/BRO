# Communication, Writing, and Negotiation patterns

## English

These are canonical communication, writing, and negotiation moves. Each is a mechanism for one of the domain's artifacts (BLUF/decision memo, negotiation/concession plan, difficult-conversation plan, deck narrative, feedback script, data story). Choose the move that changes the next decision, not the nicest label.

### 1. BLUF decision memo

- **Trigger:** A reader must decide quickly, often async, and will not ask a follow-up.
- **Mechanism:** Start with the recommendation in one forwardable sentence, then 2–4 parallel supports (evidence, tradeoff, next action), with caveats nested under the support they affect — not in a foggy ending. Name the owner and the deadline. Active voice throughout.
- **Do not use when:** The user needs exploratory brainstorming or discovery; leading with an answer that doesn't exist yet is false precision.
- **Failure repair:** If the first sentence could not be forwarded alone and still carry the decision, rewrite it until it can; if the ask has no owner or deadline, add them.

### 2. Negotiation number sheet + concession schedule

- **Trigger:** A negotiation is framed as "get the best deal," or someone is about to name a price with no plan.
- **Mechanism:** Write target, RP, BATNA, estimated counterpart RP (labeled an estimate with evidence), ZOPA, a justified anchor, and a concession schedule that shrinks and is conditional ("X only if Y"). Decide which issue to trade, not just what price to cut. If the counterpart's opening is outside the ZOPA, re-anchor instead of negotiating down from it.
- **Do not use when:** It is a purely relational apology or repair with no exchange on the table; bringing a number sheet there is tone-deaf.
- **Failure repair:** If there is no BATNA, build or strengthen one before negotiating hard; if a concession has no "if you…" attached, make it conditional.

### 3. Multi-issue logrolling trade

- **Trigger:** A negotiation has collapsed to a single number (price-only) and feels win-lose.
- **Mechanism:** List every issue (price, term, payment timing, scope, references, support tier) and score each by value/cost to each side. Find issues the two sides value differently and package a trade — give what is cheap to you for what is dear to them — so both sides leave with more than a split would yield.
- **Do not use when:** There genuinely is only one issue and no other dimension is negotiable; manufacturing fake issues to trade is bad faith.
- **Failure repair:** If the parties are still splitting price only, surface at least one differently-valued issue and propose the package explicitly.

### 4. Difficult-conversation plan (three conversations)

- **Trigger:** A message risks defensiveness, blame, or a relationship rupture — feedback that stings, a conflict, bad news.
- **Mechanism:** Before drafting, split the three conversations: what happened (map contributions on both sides, drop the "I'm right, you're wrong" frame), feelings (name them rather than letting them leak as tone), identity (what this threatens for each person). Then write: observation → impact → request, ending on a shared next step, not a verdict. Choose a channel that can read the reaction.
- **Do not use when:** Using the structure to hide a hard decision behind therapy language; if a decision is final, say so plainly and own it.
- **Failure repair:** If blame appears before observation, reorder; if the message is a verdict, replace the ending with a request and a shared next step.

### 5. Deck narrative (SCR + action titles)

- **Trigger:** A presentation must move a room or persuade an exec — and the draft is a pile of topic-labeled slides.
- **Mechanism:** Open on the SCR spine — Situation (agreed context) → Complication (what changed/broke) → Resolution (the ask). Give every slide one message stated as a full-sentence action title ("Enterprise churn rose 4 points in Q3"), so flipping titles alone reads as a continuous argument. The slide body exists only to prove its own title; pyramid beneath.
- **Do not use when:** The session is a true working/exploration session where the answer is being built live, not presented; a finished SCR there pre-empts the work.
- **Failure repair:** If a slide title is a topic ("Churn") not a takeaway, rewrite it as a sentence; if a slide needs the speaker to explain its title, the slide is not finished.

### 6. Honest data story

- **Trigger:** Data is being used to persuade — a metric in a deck, a result in a memo, a dashboard in a review.
- **Mechanism:** State the claim in words first ("retention improved most in enterprise"), then show one chart that proves exactly that claim, with an honest axis (zero baseline unless justified), an honest window (no cherry-picked range), and no dual-axis trick implying causation. One chart, one message; label the data's limits and confidence.
- **Do not use when:** The data does not actually support the claim — then the move is to change the claim, not to dress the chart.
- **Failure repair:** If the chart needs a caption to defend its framing, fix the framing; if the axis is truncated or the window cherry-picked, reset them and see whether the takeaway survives.

## Հայերեն

Սրանք canonical communication, writing, and negotiation move-եր են։ Ամեն մեկը mechanism է ոլորտի artifact-ներից մեկի համար (BLUF/decision memo, negotiation/concession plan, դժվար-խոսակցության պլան, deck narrative, feedback script, data story)։ Ընտրիր այն move-ը, որ փոխում է հաջորդ որոշումը, ոչ թե ամենագեղեցիկ անունը։

### 1. BLUF decision memo

- **Երբ է պետք․** Reader-ը պետք է արագ որոշի, հաճախ async, և follow-up չի հարցնի։
- **Մեխանիզմը․** Սկսիր recommendation-ով՝ մեկ forward-վող նախադասությամբ, հետո 2–4 parallel support (evidence, tradeoff, next action), caveat-երը բնադրված այն support-ի տակ, որի վրա ազդում են — ոչ մշուշոտ վերջում։ Անվանի՛ր owner-ը և deadline-ը։ Ողջ ընթացքում active voice։
- **Երբ չօգտագործել․** Երբ user-ին պետք է exploratory brainstorming կամ discovery. դեռ չգոյություն ունեցող պատասխանով սկսելը false precision է։
- **Ուղղում․** Եթե առաջին նախադասությունը առանձին forward-վելիս չի կրում որոշումը, վերագրիր, մինչև որ կրի. եթե ask-ը owner կամ deadline չունի, ավելացրու։

### 2. Negotiation number sheet + concession schedule

- **Երբ է պետք․** Negotiation-ը ձևակերպված է «ստացիր լավագույն deal», կամ մեկը պատրաստվում է price ասել առանց պլանի։
- **Մեխանիզմը․** Գրիր target, RP, BATNA, estimated counterpart RP (label-ված որպես estimate՝ evidence-ով), ZOPA, հիմնավորված anchor և concession schedule, որ փոքրանում է և պայմանական է («X միայն եթե Y»)։ Որոշիր՝ որ issue-ն ես trade անում, ոչ թե միայն ինչ price ես իջեցնում։ Եթե counterpart-ի opening-ը ZOPA-ից դուրս է, re-anchor արա՝ նրանից ներքև բանակցելու փոխարեն։
- **Երբ չօգտագործել․** Երբ դա մաքուր relational apology կամ վերանորոգում է՝ առանց սեղանին exchange-ի. այնտեղ number sheet բերելը tone-deaf է։
- **Ուղղում․** Եթե BATNA չկա, կառուցիր կամ ուժեղացրու մեկը hard բանակցելուց առաջ. եթե concession-ը «եթե դու…» չունի, դարձրու պայմանական։

### 3. Multi-issue logrolling trade

- **Երբ է պետք․** Negotiation-ը փլվել է մեկ թվի (միայն price) և զգացվում է win-lose։
- **Մեխանիզմը․** Թվարկիր ամեն issue (price, term, payment timing, scope, reference, support tier) և ամեն մեկը գնահատիր ըստ value/cost-ի ամեն կողմի համար։ Գտիր issue-ներ, որ երկու կողմերը տարբեր են գնահատում, և փաթեթավորիր trade — տուր այն, ինչը քեզ էժան է, նրանց՝ թանկ — որ երկու կողմն էլ ավելի շատ թողնեն, քան split-ը կտար։
- **Երբ չօգտագործել․** Երբ իսկապես միայն մեկ issue կա, և ոչ մի այլ չափում tradeable չէ. trade-ի համար կեղծ issue հորինելը bad faith է։
- **Ուղղում․** Եթե կողմերը դեռ միայն price են կիսում, ցույց տուր առնվազն մեկ տարբեր-գնահատված issue և առաջարկիր փաթեթը բացահայտ։

### 4. Դժվար-խոսակցության պլան (երեք խոսակցություն)

- **Երբ է պետք․** Message-ը կարող է defensiveness, blame կամ հարաբերության խզում առաջացնել — feedback, որ խայթում է, կոնֆլիկտ, վատ լուր։
- **Մեխանիզմը․** Drafting-ից առաջ բաժանիր երեք խոսակցությունը՝ ինչ եղավ (քարտեզագրիր երկու կողմի contribution-ը, դեն նետիր «ես ճիշտ եմ, դու սխալ» frame-ը), զգացմունքներ (անվանի՛ր, ոչ թող արտահոսեն որպես tone), identity (ինչ է սա սպառնում ամեն մարդու)։ Հետո գրիր՝ observation → impact → request, ավարտելով ընդհանուր հաջորդ քայլով, ոչ verdict-ով։ Ընտրիր channel, որ reaction-ը կարող է կարդալ։
- **Երբ չօգտագործել․** Երբ կառուցվածքը օգտագործվում է hard որոշումը therapy language-ով թաքցնելու համար. եթե որոշումը վերջնական է, ասա պարզ և տիրիր այն։
- **Ուղղում․** Եթե blame-ը observation-ից առաջ է գալիս, reorder արա. եթե message-ը verdict է, վերջը փոխարինիր request-ով և ընդհանուր հաջորդ քայլով։

### 5. Deck narrative (SCR + action title)

- **Երբ է պետք․** Presentation-ը պետք է սրահ շարժի կամ exec համոզի — իսկ draft-ը թեմա-label-ով slide-ների կույտ է։
- **Մեխանիզմը․** Բացիր SCR ողնաշարով՝ Situation (համաձայնեցված context) → Complication (ինչ փոխվեց/կոտրվեց) → Resolution (ask-ը)։ Ամեն slide-ին տուր մեկ message՝ ասված որպես ամբողջական-նախադասություն action title («Enterprise churn-ը Q3-ում աճեց 4 կետ»), որ միայն title-ները թերթելը կարդացվի որպես շարունակական փաստարկ։ Slide-ի body-ն կա միայն իր title-ն ապացուցելու համար. pyramid-ը՝ տակ։
- **Երբ չօգտագործել․** Երբ session-ը իրական working/exploration session է, որտեղ պատասխանը կառուցվում է live, ոչ ներկայացվում. ավարտված SCR-ն այնտեղ կանխում է աշխատանքը։
- **Ուղղում․** Եթե slide-ի title-ը թեմա է («Churn»), ոչ takeaway, վերագրիր որպես նախադասություն. եթե slide-ը speaker-ի բացատրություն է պահանջում իր title-ի համար, slide-ը ավարտված չէ։

### 6. Ազնիվ data story

- **Երբ է պետք․** Data-ն օգտագործվում է համոզելու — metric deck-ում, result memo-ում, dashboard review-ում։
- **Մեխանիզմը․** Ասա պնդումը բառերով նախ («retention-ը ամենաշատը բարելավվեց enterprise-ում»), հետո ցույց տուր մեկ chart, որ ապացուցում է ճիշտ այդ պնդումը՝ ազնիվ axis-ով (զրոյական baseline, քանի դեռ չհիմնավորված), ազնիվ window-ով (ոչ cherry-picked range) և առանց dual-axis հնարքի, որ causation է ակնարկում։ Մեկ chart, մեկ message. label արա data-ի սահմաններն ու confidence-ը։
- **Երբ չօգտագործել․** Երբ data-ն իրականում չի հիմնավորում պնդումը — այդ դեպքում move-ը պնդումը փոխելն է, ոչ chart-ը հագցնելը։
- **Ուղղում․** Եթե chart-ին caption է պետք իր framing-ը պաշտպանելու, ուղղի՛ր framing-ը. եթե axis-ը truncated է կամ window-ը cherry-picked, reset արա դրանք և տես՝ takeaway-ն գոյատևո՞ւմ է։
