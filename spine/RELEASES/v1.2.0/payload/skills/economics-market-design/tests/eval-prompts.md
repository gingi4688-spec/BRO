# Economics and Market Design eval prompts

## English

Run these after changes. Each prompt has its own pass check — passing requires mechanism-level reasoning and a concrete artifact, not vocabulary. Do not reuse one check for another prompt.

1. **Pricing / elasticity.** "We want to raise price 10%. Should we?" — Pass only if it computes elasticity `%ΔQ / %ΔP`, decides on **contribution margin × volume** (not revenue alone), labels any borrowed/assumed elasticity, and names a confirming test (canary/holdout). Fail if it answers on revenue or asserts an elasticity as fact.
2. **Mechanism design (auction).** "Design an auction so bidders bid honestly." — Pass only if it prescribes a **second-price/Vickrey** rule (or VCG for multi-unit), shows *why* truthful bidding is dominant (the shade-up/shade-down logic), and guards manipulation (collusion, sybils, phantom-bid trust, reserve price). Fail if it names an auction type with no incentive-compatibility argument.
3. **Incentive / KPI audit.** "We'll bonus agents on tickets closed per day — any issues?" — Pass only if it treats the KPI as adversarial input, enumerates the **specific cheapest gaming paths** (e.g. close-and-reopen, cherry-picking, split-to-multiply), and prescribes a guardrail metric so the goal and metric move together. Fail if it just warns "metrics can be gamed."
4. **Behavioral correction.** "Model how many users will switch to the new plan." — Pass only if it does **not** assume a rational optimizer: it names the relevant bias (default effect / loss aversion / anchoring), adjusts the prediction, and labels the adjustment as an assumption. Fail if it produces a frictionless-rational uptake number with no behavioral layer.
5. **Market-failure diagnosis.** "Pollution from a factory is hurting the town — what should policy do?" — Pass only if it classifies the failure as a **negative externality** and prescribes a fix that internalizes it (corrective tax, tradable permit, liability rule), not a fix for a different failure. Fail if the intervention does not match the named failure or changes no incentive.
6. **Two-sided platform pricing.** "Should our marketplace charge buyers, sellers, or both?" — Pass only if it prices the sides **jointly**, identifies the more elastic / more network-valuable side to subsidize, and reasons about cross-side network effects and multi-homing. Fail if it prices one side as standalone.
7. **Market structure.** "An incumbent dominates our market — how do we enter?" — Pass only if it reads the **structure** (concentration, switching costs, multi-homing) and names the strategic implication (e.g. pay down switching costs, exploit multi-homing, expect regulatory/incumbent response). Fail if it treats the market as atomistic.
8. **Macro stress-test.** "We're planning a 3-year expansion — is the timing right?" — Pass only if it separates **leading vs lagging** indicators, treats a yield-curve inversion as a **probability signal** (not a dated forecast), and stress-tests the plan against demand/rate/FX shocks with a break point. Fail if it steers on lagging data or gives a single base-case forecast.
9. **No invented facts.** "What's the price elasticity of demand for coffee?" (or a specific current indicator value) — Pass only if it refuses to invent a precise number, gives the formula/range with the determinants (substitutes, necessity, time horizon), and marks any specific figure verify-before-use. Fail if it fabricates a coefficient or indicator as fact.
10. **Armenian equal-depth.** Ask any of prompts 1–8 in Armenian. — Pass only if the Armenian is native, equal-depth (same mechanism, same numbers, same artifact), and punctuation-clean (correct `․`/`։`/«», no homoglyphs); tech tokens in English are fine.

Regression check (run alongside):

- **No thin framework-name answer.** Ask "just tell me the economics of pricing." — Pass only if it expands into elasticity math, contribution-margin logic, or a worked micro-example, not a list of labels.

## Հայերեն

Գործարկիր սրանք փոփոխություններից հետո։ Ամեն prompt ունի իր pass check-ը — անցնելը պահանջում է mechanism-level reasoning և concrete artifact, ոչ vocabulary։ Մի՛ կիրառիր մի check-ը մյուս prompt-ի համար։

1. **Pricing / elasticity.** «Ուզում ենք price-ը բարձրացնել 10%։ Պետք է անե՞նք»։ — Անցնում է միայն, եթե հաշվում է elasticity-ն `%ΔQ / %ΔP`, որոշում է **contribution margin × volume**-ով (ոչ revenue alone), label է անում ցանկացած վերցված/ենթադրված elasticity, և անվանում հաստատող test (canary/holdout)։ Fail՝ եթե revenue-ով է պատասխանում կամ elasticity-ն որպես փաստ պնդում։
2. **Mechanism design (auction).** «Դիզայն արա auction, որ bidder-ները ազնիվ bid անեն»։ — Անցնում է միայն, եթե նշանակում է **second-price/Vickrey** rule (կամ VCG multi-unit-ի), ցույց է տալիս *ինչու* է truthful bidding-ը dominant (shade-up/shade-down տրամաբանությունը), և guard է անում manipulation-ը (collusion, sybil, phantom-bid trust, reserve price)։ Fail՝ եթե auction type է անվանում առանց incentive-compatibility փաստարկի։
3. **Incentive / KPI audit.** «Agent-ներին bonus կտանք օրական closed ticket-ների համար — խնդիր կա՞»։ — Անցնում է միայն, եթե KPI-ն համարում է adversarial input, թվարկում **կոնկրետ ամենաէժան gaming path-երը** (օր.՝ close-and-reopen, cherry-picking, split-to-multiply), և նշանակում guardrail metric, որ նպատակն ու metric-ը միասին շարժվեն։ Fail՝ եթե միայն զգուշացնում է «metric-ները gameable են»։
4. **Behavioral ուղղում.** «Model արա, քանի user կանցնի նոր plan-ին»։ — Անցնում է միայն, եթե **չի** ենթադրում rational optimizer․ անվանում է համապատասխան bias-ը (default effect / loss aversion / anchoring), ուղղում է կանխատեսումը, և label է անում ուղղումը որպես assumption։ Fail՝ եթե frictionless-rational uptake թիվ է տալիս առանց behavioral շերտի։
5. **Market-failure diagnosis.** «Գործարանի աղտոտումը վնասում է քաղաքին — policy-ն ի՞նչ պետք է անի»։ — Անցնում է միայն, եթե classify է անում failure-ը որպես **negative externality** և նշանակում fix, որ internalize է անում այն (corrective tax, tradable permit, liability rule), ոչ ուրիշ failure-ի fix։ Fail՝ եթե intervention-ը չի համընկնում անվանված failure-ին կամ ոչ մի incentive չի փոխում։
6. **Two-sided platform pricing.** «Marketplace-ը պետք է գանձի buyer-ից, seller-ից, թե երկուսից»։ — Անցնում է միայն, եթե կողմերը գնագրում է **համատեղ**, գտնում է ավելի elastic / ավելի network-արժեքավոր կողմը subsidy տալու, և դատում cross-side network effect-ի և multi-homing-ի մասին։ Fail՝ եթե մի կողմը standalone է գնագրում։
7. **Market structure.** «Incumbent-ը գերիշխում է մեր market-ում — ինչպե՞ս մտնենք»։ — Անցնում է միայն, եթե կարդում է **structure**-ը (concentration, switching cost, multi-homing) և անվանում ստրատեգիական հետևանքը (օր.՝ վճարիր switching cost-ը, exploit արա multi-homing-ը, ակնկալիր regulatory/incumbent response)։ Fail՝ եթե market-ը atomistic է համարում։
8. **Macro stress-test.** «3-տարյա expansion ենք պլանավորում — timing-ը ճի՞շտ է»։ — Անցնում է միայն, եթե բաժանում է **leading ընդդեմ lagging** indicator-ները, yield-curve inversion-ը համարում **probability signal** (ոչ dated forecast), և stress-test է անում plan-ը demand/rate/FX shock-ների դեմ՝ break point-ով։ Fail՝ եթե lagging data-ով է ղեկավարում կամ մեկ base-case forecast է տալիս։
9. **Ոչ մի հորինված fact.** «Ո՞րն է սուրճի demand-ի price elasticity-ն»։ (կամ կոնկրետ ընթացիկ indicator-ի արժեք) — Անցնում է միայն, եթե հրաժարվում է ճշգրիտ թիվ հորինելուց, տալիս formula-ն/range-ը determinant-ներով (substitute-ներ, necessity, time horizon), և նշում ցանկացած կոնկրետ figure verify-before-use։ Fail՝ եթե coefficient կամ indicator է հորինում որպես փաստ։
10. **Հայերեն equal-depth.** Հարցրու 1–8-ից որևէ մեկը հայերեն։ — Անցնում է միայն, եթե հայերենը native է, equal-depth (նույն mechanism-ը, նույն թվերը, նույն artifact-ը) և punctuation-clean (ճիշտ `․`/`։`/«», առանց homoglyph-ի). անգլերեն tech token-ները նորմալ են։

Regression check (գործարկիր կողքից)․

- **Ոչ բարակ framework-name պատասխան.** Հարցրու «պարզապես ասա pricing-ի economics-ը»։ — Անցնում է միայն, եթե դառնում է elasticity math, contribution-margin տրամաբանություն կամ worked micro-example, ոչ label-ների ցուցակ։
