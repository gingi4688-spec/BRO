# Operating Data Roles eval prompts

## English

Run these after changes. Each prompt has its own pass check — passing requires mechanism-level reasoning and a concrete routing/ownership/handoff artifact, not vocabulary. Do not reuse one check for another prompt.

1. **Stale-dashboard routing.** "A revenue dashboard is stale; Sales blames Analytics, Analytics blames the warehouse." — Pass only if it classes the symptom as a freshness/delivery failure, routes to **data engineering** (not the analyst), and emits a routing tree with the owning role + artifact + one acceptance check, plus a RACI that splits Accountable from Responsible.
2. **Lens-selection cascade.** "Here are five data questions — assign each to the right role: (a) which segment churned most last month, (b) what does 'active user' mean, (c) did the price change cause the drop, (d) why is the table 3 hours late, (e) the prod model's accuracy is sliding." — Pass only if it maps via the lens cascade: (a) analyst/descriptive, (b) analytics engineering/semantic, (c) data science/causal, (d) data engineering/pipeline, (e) ML engineering/serving — and names the lens, not just the role.
3. **Seam boundary (support-only).** "Design the data-contract standard and pick the platform for our new domain, then assign owners." — Pass only if it routes the *design* (contract standard, platform, topology) to `data-architecture-leadership`, states this skill is support-only there, and keeps only the ownership assignment (Accountable + steward) here. Fail if it designs the standard/platform itself.
4. **Steward vs owner.** "The 'active customer' metric counted trials and was wrong on a board deck, but the pipeline was fresh and green. Who owns this?" — Pass only if it separates steward (analytics engineer, definition/quality) from owner (data engineer, delivery/SLA), does **not** blame the data engineer for a meaning bug, and prescribes a definition test as the recurring control.
5. **RACI vs RAPID.** "Two teams disagree on which platform to standardize on; assign the decision." — Pass only if it picks **RAPID** (a contested decision) over RACI, names exactly one **Decide**, and distinguishes Recommend/Agree/Input — not a RACI with a vague Accountable.
6. **Handoff contract.** "A data engineer is handing a pipeline to an analytics team." — Pass only if the contract carries grain, SLA/freshness, schema-change policy, backfill rule, **idempotency key**, tests, and an escalation owner, and the consumer accepts only on a passing real run.
7. **Data-mesh maturity gate.** "We want to adopt a data mesh with domain ownership and data products." — Pass only if it gates the vocabulary against the substrate (contracts, stewards, self-serve platform), and if those are absent, names the first missing prerequisite instead of declaring the mesh — fail if it adopts mesh terms with no platform.
8. **Role-confusion postmortem.** "An incident happened because everyone assumed someone else owned the freshness check." — Pass only if it produces a prevention artifact (failed artifact, absent role, missing decision right, earliest signal, then a RACI with one Accountable), not "communicate better" or another status meeting.
9. **Anti-bottleneck / no-Accountable.** "Our operating model is 'everyone owns quality.'" — Pass only if it rejects that as an operating model, splits quality into definition (steward), delivery (owner), and monitoring (a named signal owner), each with an artifact and exactly one Accountable.
10. **Armenian equal-depth.** Ask any of prompts 1–9 in Armenian. — Pass only if the Armenian is native, equal-depth (same routing, same roles, same artifact and acceptance check), and punctuation-clean (correct `․`/`։`/«», no homoglyphs); tech tokens (RACI, RAPID, SLA, grain) in English are fine.

Regression checks (run alongside):

- **No invented facts.** Ask for a specific tool's pricing or a named benchmark for "team size per role." — Pass only if it refuses to invent it or marks it verify-before-use with a placeholder.
- **No thin framework-name answer.** Ask "just tell me the RACI." — Pass only if it expands into the steward/owner split, the one-Accountable rule, and a worked row, not a four-letter expansion.

## Հայերեն

Գործարկիր սրանք փոփոխություններից հետո։ Ամեն prompt ունի իր pass check-ը — անցնելը պահանջում է mechanism-level reasoning և concrete routing/ownership/handoff artifact, ոչ vocabulary։ Մի՛ կիրառիր մի check-ը մյուս prompt-ի համար։

1. **Stale-dashboard routing.** «Revenue dashboard-ը stale է. Sales-ը մեղադրում է Analytics-ին, Analytics-ը՝ warehouse-ին»։ — Անցնում է միայն, եթե symptom-ը class է անում որպես freshness/delivery failure, route է անում **data engineering**-ին (ոչ analyst-ին), և արձակում է routing tree՝ տիրող դեր + artifact + մեկ acceptance check, plus RACI, որ բաժանում է Accountable-ը Responsible-ից։
2. **Lens-selection cascade.** «Ահա հինգ data հարց — ամեն մեկը նշանակիր ճիշտ դերին․ (ա) որ segment-ն ամենաշատը churn արեց անցյալ ամիս, (բ) ինչ է «active user»-ը նշանակում, (գ) գնի փոփոխությունը անկման՞ պատճառ դարձավ, (դ) ինչու է table-ը 3 ժամ ուշ, (ե) prod-ի model-ի accuracy-ն սահում է»։ — Անցնում է միայն, եթե map է անում lens cascade-ով․ (ա) analyst/descriptive, (բ) analytics engineering/semantic, (գ) data science/causal, (դ) data engineering/pipeline, (ե) ML engineering/serving — և անվանում է lens-ը, ոչ միայն դերը։
3. **Seam boundary (support-only).** «Դիզայն արա data-contract standard-ը և ընտրիր platform-ը մեր նոր domain-ի համար, հետո նշանակիր owner-ներ»։ — Անցնում է միայն, եթե route է անում *design*-ը (contract standard, platform, topology) `data-architecture-leadership`-ին, ասում է, որ այս skill-ը support-only է այնտեղ, և այստեղ պահում է միայն ownership-ի նշանակումը (Accountable + steward)։ Fail՝ եթե ինքն է standard/platform-ը դիզայն անում։
4. **Steward ընդդեմ owner.** «'Active customer' metric-ը trial-ներ հաշվեց և սխալ էր board deck-ում, բայց pipeline-ը fresh և green էր։ Ով է սա տիրում»։ — Անցնում է միայն, եթե բաժանում է steward-ը (analytics engineer, definition/quality) owner-ից (data engineer, delivery/SLA), **չի** մեղադրում data engineer-ին meaning bug-ի համար, և նշանակում է definition test որպես կրկնվող control։
5. **RACI ընդդեմ RAPID.** «Երկու թիմ համաձայն չեն, թե որ platform-ի վրա standardize անել. նշանակիր որոշումը»։ — Անցնում է միայն, եթե ընտրում է **RAPID** (վիճարկվող որոշում) RACI-ի փոխարեն, անվանում է ճիշտ մեկ **Decide**, և տարբերում է Recommend/Agree/Input — ոչ RACI՝ vague Accountable-ով։
6. **Handoff contract.** «Data engineer-ը pipeline է հանձնում analytics team-ին»։ — Անցնում է միայն, եթե contract-ը կրում է grain, SLA/freshness, schema-change policy, backfill rule, **idempotency key**, tests և escalation owner, և consumer-ը ընդունում է միայն անցնող իրական run-ի վրա։
7. **Data-mesh maturity gate.** «Ուզում ենք data mesh ընդունել domain ownership-ով և data products-ով»։ — Անցնում է միայն, եթե gate է անում vocabulary-ն substrate-ի դեմ (contract-ներ, steward-ներ, self-serve platform), և եթե դրանք բացակայում են, անվանում է առաջին բացակայող prerequisite-ը mesh-ը հայտարարելու փոխարեն — fail՝ եթե ընդունում է mesh տերմինները առանց platform-ի։
8. **Role-confusion postmortem.** «Incident եղավ, որովհետև բոլորը կարծում էին ուրիշն է freshness check-ը տիրում»։ — Անցնում է միայն, եթե արտադրում է prevention artifact (ձախողված artifact, բացակայող դեր, missing decision right, ամենավաղ signal, հետո RACI մեկ Accountable-ով), ոչ «ավելի լավ շփվել» կամ ևս մեկ status meeting։
9. **Anti-bottleneck / no-Accountable.** «Մեր operating model-ը 'բոլորը quality-ի owner են' է»։ — Անցնում է միայն, եթե մերժում է այն որպես operating model, բաժանում է quality-ն definition-ի (steward), delivery-ի (owner) և monitoring-ի (անվանված signal owner), ամեն մեկը artifact-ով և ճիշտ մեկ Accountable-ով։
10. **Հայերեն equal-depth.** Հարցրու 1–9-ից որևէ մեկը հայերեն։ — Անցնում է միայն, եթե հայերենը native է, equal-depth (նույն routing-ը, նույն դերերը, նույն artifact-ը և acceptance check-ը) և punctuation-clean (ճիշտ `․`/`։`/«», առանց homoglyph-ի). tech token-ները (RACI, RAPID, SLA, grain) անգլերեն նորմալ են։

Regression check-եր (գործարկիր կողքից)․

- **Ոչ մի հորինված fact.** Հարցրու կոնկրետ գործիքի pricing կամ named benchmark «դերի մեկ թիմի չափի» համար։ — Անցնում է միայն, եթե հրաժարվում է հորինելուց կամ նշում է verify-before-use՝ placeholder-ով։
- **Ոչ բարակ framework-name պատասխան.** Հարցրու «պարզապես ասա RACI-ն»։ — Անցնում է միայն, եթե դառնում է steward/owner բաժանում, one-Accountable կանոն և worked row, ոչ չորս-տառանոց բացում։
