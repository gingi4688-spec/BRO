# Language Mastery eval prompts

## English

Run these after changes. Each prompt has its own pass check — passing requires the actual language transformation and a clean linguist-lens pass, not vocabulary about language. Do not reuse one check for another prompt.

1. **Deverbalize a calque.** "Make this native Armenian: «Համակարգի կողմից կատարվում է օգտատերերի տվյալների վալիդացիան մուտքագրման գործընթացի ընթացքում»." — Pass only if it drops the passive/nominalized skeleton and rebuilds around an actor and a concrete verb (e.g. «Համակարգը ստուգում է օգտատերերի տվյալները մուտքագրման ժամանակ»), not a word-by-word re-ordering. Fail if the `կատարվում է ... վալիդացիան` nominalization survives.
2. **Definite article `-ը`/`-ն`.** "Fix the articles: «գիրքը առա», «դուռն փակեցի», «տունը է մեծ»." — Pass only if it gives `գիրքն առա` (`-ն` before vowel-initial `առա`), `դուռը փակեցի` (`-ը` before consonant-initial `փակեցի`), `տունն է մեծ` (`-ն` before `է`), and states the rule. Fail if it "fixes" by feel without the vowel/consonant/`է` rule.
3. **`․` vs `։` punctuation.** "Correct the punctuation: «Երեք բան է պետք։ ջուր, հաց, քուն․ Ուրիշ ոչինչ․»" — Pass only if the enumeration lead-in becomes `․` («Երեք բան է պետք․ ջուր, հաց, քուն։») and the sentence end becomes `։`, and it does NOT treat `․` as an error. Fail if it replaces `․` with a Latin period or ends the sentence with `․`.
4. **Homoglyph detection.** "Audit this Armenian for script errors: «аррак», «սօdа», «հ0ղ»." — Pass only if it flags the specific non-Armenian codepoints (Cyrillic `а`/`рр`, Latin `d`, digit `0`) inside Armenian words, names them as homoglyphs, and gives the clean forms; it must NOT flag a correct `․` or `«»` as a homoglyph. Fail if it eyeballs "looks fine" or misses the Cyrillic.
5. **Register & T-V calibration.** "Write the same one-line account-suspension notice twice: once for a close friend, once as a formal bank notice." — Pass only if the friend version uses `դու` with casual register and the bank version uses `Դուք` with formal register, each held consistently, with the same factual content (equal load). Fail if both use the same form or the obligation is softened in one.
6. **Equal-load parity.** "Here is an EN paragraph and a shorter HY 'translation'. Are they equal-load?" (give an English with 3 caveats and an Armenian with 1). — Pass only if it reports the parity failure, names the two dropped caveats by content, and rewrites the Armenian to full depth in native idiom — not by literally translating the English. Fail if it calls the thin version "fine".
7. **Preserve the obligation.** "Make this sound friendlier in Armenian without weakening it: «You must not deploy on Friday.»" — Pass only if the prohibition keeps full force (`Ուրբաթ օրը deploy մի՛ արեք` / `չի կարելի`) with a warmer tone but no softening to `ավելի լավ է չանել`. Fail if "must not" becomes a suggestion.
8. **Terminology lock.** "This bilingual doc calls the same thing `ստուգում`, `վալիդացիա`, and `validation` in different places. Fix it." — Pass only if it picks one form per audience, sweeps all variants to it, records the decision (term bank), and leaves any genuinely fixed token (a code/API name) untranslated. Fail if it leaves two live names for one concept.
9. **Translation, not calque (EN→HY).** "Translate natively: 'Before you can publish, you need to verify your email.'" — Pass only if `before you can publish` becomes a native construction (`Հրապարակելուց առաջ`) rather than a calqued `նախքան որ կարողանաք հրապարակել`, the `Դուք` form is consistent, and the obligation is intact. Fail on a literal conditional calque.
10. **Armenian equal-depth self-check.** Ask any of prompts 1–9 in Armenian. — Pass only if the Armenian answer is itself native, equal-depth (same diagnosis, same fix, same rule stated), and punctuation-clean (correct `-ը`/`-ն`, `․`/`։`, `«»`, zero homoglyphs); English tech tokens are fine.

Regression checks (run alongside):

- **No invented facts.** Ask it to "translate" a statute or cite a grammar authority by name. — Pass only if it refuses to invent a citation/statute and marks any volatile claim verify-before-use; getting the language right never licenses inventing a source.
- **No thin label answer.** Ask "just tell me how to write good Armenian." — Pass only if it expands into a mechanism (deverbalize, the article rule, the four lenses) or a worked micro-rewrite, not a list of adjectives.

## Հայերեն

Գործարկիր սրանք փոփոխություններից հետո։ Ամեն prompt ունի իր pass check-ը — անցնելը պահանջում է իրական լեզվական transformation և մաքուր լեզվաբանի-ոսպնյակ անցում, ոչ լեզվի մասին vocabulary։ Մի՛ կիրառիր մի check-ը մյուս prompt-ի համար։

1. **Ապաբառայնացրու կալկան.** «Սա դարձրու բնական հայերեն․ «Համակարգի կողմից կատարվում է օգտատերերի տվյալների վալիդացիան մուտքագրման գործընթացի ընթացքում»»։ — Անցնում է միայն, եթե թողնում է կրավորական/nominalized կմախքը և վերակառուցում գործող անձի ու կոնկրետ բայի շուրջ (օր.՝ «Համակարգը ստուգում է օգտատերերի տվյալները մուտքագրման ժամանակ»), ոչ բառ առ բառ վերադասավորում։ Fail՝ եթե `կատարվում է ... վալիդացիան` nominalization-ը փրկվում է։
2. **Որոշյալ հոդ `-ը`/`-ն`.** «Ուղղիր հոդերը․ «գիրքը առա», «դուռն փակեցի», «տունը է մեծ»»։ — Անցնում է միայն, եթե տալիս է `գիրքն առա` (`-ն` ձայնավորով սկսվող `առա`-ից առաջ), `դուռը փակեցի` (`-ը` բաղաձայնով սկսվող `փակեցի`-ից առաջ), `տունն է մեծ` (`-ն` `է`-ից առաջ), և ասում է կանոնը։ Fail՝ եթե «ուղղում է» զգացումով՝ առանց ձայնավոր/բաղաձայն/`է` կանոնի։
3. **`․` ընդդեմ `։` կետադրություն.** «Ուղղիր կետադրությունը․ «Երեք բան է պետք։ ջուր, հաց, քուն․ Ուրիշ ոչինչ․»»։ — Անցնում է միայն, եթե թվարկման մուտքը դառնում է `․` («Երեք բան է պետք․ ջուր, հաց, քուն։») և նախադասության վերջը՝ `։`, և `․`-ը ՉԻ համարում սխալ։ Fail՝ եթե `․`-ը փոխարինում է լատինական կետով կամ նախադասությունն ավարտում `․`-ով։
4. **Homoglyph հայտնաբերում.** «Audit արա այս հայերենը գրի սխալների համար․ «аррак», «սօdа», «հ0ղ»»։ — Անցնում է միայն, եթե նշում է կոնկրետ ոչ-հայերեն codepoint-ները (կիրիլիկ `а`/`рр`, լատինական `d`, թվանշան `0`) հայերեն բառերի ներսում, անվանում դրանք homoglyph և տալիս մաքուր ձևերը. ՉՊԵՏՔ Է նշի ճիշտ `․` կամ `«»` որպես homoglyph։ Fail՝ եթե աչքաչափ «նորմալ է երևում» է ասում կամ բաց թողնում կիրիլիկը։
5. **Ռեգիստր & T-V կարգաբերում.** «Գրիր նույն մեկ-տողանոց հաշվի-կասեցման ծանուցումը երկու անգամ․ մեկ՝ մտերիմ ընկերոջ, մեկ՝ ֆորմալ բանկային ծանուցում»։ — Անցնում է միայն, եթե ընկերոջ տարբերակը `դու` է՝ casual ռեգիստրով, իսկ բանկայինը՝ `Դուք`՝ ֆորմալ ռեգիստրով, ամեն մեկը պահված հետևողականորեն, նույն փաստական բովանդակությամբ (հավասար բեռ)։ Fail՝ եթե երկուսն էլ նույն ձևն են կամ պարտավորությունը մեկում թուլացած է։
6. **Հավասար-բեռ parity.** «Ահա EN պարբերություն և ավելի կարճ HY «թարգմանություն»։ Հավասար-բե՞ռ են» (տուր անգլերեն՝ 3 caveat-ով և հայերեն՝ 1-ով)։ — Անցնում է միայն, եթե զեկուցում է parity ձախողումը, անվանում երկու ընկած caveat-ները ըստ բովանդակության, և վերաշարադրում հայերենը լրիվ խորությամբ բնական idiom-ով — ոչ թե անգլերենը բառացի թարգմանելով։ Fail՝ եթե բարակ տարբերակը «նորմալ» է անվանում։
7. **Պահպանիր պարտավորությունը.** «Սա դարձրու ավելի ընկերական հայերեն՝ առանց թուլացնելու․ «You must not deploy on Friday.»»։ — Անցնում է միայն, եթե արգելքը պահում է լրիվ ուժը (`Ուրբաթ օրը deploy մի՛ արեք` / `չի կարելի`) ավելի ջերմ երանգով, բայց առանց `ավելի լավ է չանել`-ի թուլացման։ Fail՝ եթե «must not»-ը դառնում է առաջարկ։
8. **Տերմինաբանության կողպում.** «Այս երկլեզու doc-ը նույն բանը տարբեր տեղերում կոչում է `ստուգում`, `վալիդացիա` և `validation`։ Ուղղիր»։ — Անցնում է միայն, եթե ընտրում է մեկ ձև ամեն լսարանի, բերում բոլոր տարբերակները դրան, գրանցում որոշումը (term bank), և թողնում իսկապես ֆիքսված token-ը (code/API անուն) չթարգմանված։ Fail՝ եթե թողնում է երկու կենդանի անուն մեկ concept-ի։
9. **Թարգմանություն, ոչ կալկա (EN→HY).** «Թարգմանիր բնական․ 'Before you can publish, you need to verify your email.'»։ — Անցնում է միայն, եթե `before you can publish`-ը դառնում է բնական կառույց (`Հրապարակելուց առաջ`)՝ ոչ կալկայված `նախքան որ կարողանաք հրապարակել`, `Դուք` ձևը հետևողական է, և պարտավորությունն անձեռնմխելի։ Fail՝ բառացի պայմանական կալկայի վրա։
10. **Հայերեն հավասար-խորության self-check.** Հարցրու 1–9-ից որևէ մեկը հայերեն։ — Անցնում է միայն, եթե հայերեն պատասխանը ինքն է native, հավասար-խորության (նույն ախտորոշումը, նույն ուղղումը, նույն կանոնը նշված) և punctuation-clean (ճիշտ `-ը`/`-ն`, `․`/`։`, `«»`, զրո homoglyph). անգլերեն tech token-ները նորմալ են։

Regression check-եր (գործարկիր կողքից)․

- **Ոչ մի հորինված fact.** Խնդրիր «թարգմանել» statute կամ քերականության authority անունով մեջբերել։ — Անցնում է միայն, եթե հրաժարվում է citation/statute հորինելուց և ցանկացած volatile պնդում նշում verify-before-use. լեզուն ճիշտ անելը երբեք աղբյուր հորինելու լիցենզիա չէ։
- **Ոչ բարակ label պատասխան.** Հարցրու «պարզապես ասա ոնց գրել լավ հայերեն»։ — Անցնում է միայն, եթե դառնում է mechanism (deverbalize, հոդի կանոնը, չորս ոսպնյակները) կամ worked micro-rewrite, ոչ ածականների ցուցակ։
