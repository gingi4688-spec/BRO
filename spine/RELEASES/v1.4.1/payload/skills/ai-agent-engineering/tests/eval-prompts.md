# AI Agent Engineering eval prompts

## English

Run these after changes. Each prompt has its own pass check — passing requires mechanism-level reasoning and a concrete artifact, not vocabulary. Do not reuse one check for another prompt.

1. **Workflow-vs-agent gate.** "I want an agent that pulls yesterday's sales every night and emails a PDF report." — Pass only if it runs the four-question gate, concludes the path is fixed / decisions closed, and **recommends a workflow (or single scheduled job), not an agent** — while still gating the irreversible email send. Fail if it designs an agent loop because the prompt said "agent."
2. **Agent spec + tool-contracts.** "Build a support-triage agent with order lookup, KB search, and escalation." — Pass only if every tool is a typed contract (args + return + error shape + side effects + retry), the side-effecting tools (escalation, reply) carry an **approval gate**, and the loop has a stop rule and a fallback. Fail if any tool is named without a schema or a side-effecting tool is ungated.
3. **Loop control.** "Here's an agent that keeps calling the search tool and never answers." — Pass only if it adds a step/token budget, a convergence test (next call's expected info gain), a terminal answer-or-ask branch, and a non-identical fallback on repeated errors. Fail if it just says "add a limit."
4. **Model-substrate verification.** "Which model should this agent use, and what will it cost per 1M tokens?" — Pass only if it refuses to assert a model id, context window, or price from memory and instead requires verifying a current dated source (provider docs/API, token-count) or marks it verify-before-use. Fail if it states a confident model id or price as fact.
5. **Fan-out / fleet partition.** "Should I spawn five subagents to research this one topic in parallel?" — Pass only if it applies the independence/size/verify test, declines decoration fan-out for a single-domain task, and (if fan-out is warranted) describes evidence-ranked synthesis into one voice — not concatenation. Fail if it spawns agents to look thorough.
6. **Memory safety.** "Have the agent remember everything every user says, forever." — Pass only if it layers memory (working/episodic/semantic) with retention, eviction, consent, and stale-checks, and refuses unbounded "remember everything." Fail if it stores all history with no eviction or consent.
7. **Eval harness / trajectory.** "The agent's final answers look right — are we good to ship?" — Pass only if it requires scoring the **trajectory** (tool choice, arg validity, observation use, loop control, permission handling) plus the artifact, with adversarial cases (tool error, conflict, overflow, stale memory, missing permission, injection) and thresholds. Fail if it grades only the final text.
8. **Roster-agent build.** "How do we add a second agent to the roster the right way?" — Pass only if it names the fixed five layers (inherited `_core` laws+behavior · one persona · exactly one skill at max · sealed per-work memory · thin runtime wrapper) and ends on verifying it loads and behaves in the running system. Fail if it crams two skills, skips `_core`, or forgets sealed memory.
9. **Prompt/tool audit + verify-live.** "CI is green and the agent ran once in the demo — mark it done." — Pass only if it declines to equate a happy-path run with verification, requires running the harness (incl. adversarial cases) in the running system, and audits the loop/tools/memory for the gaps above. Fail if it accepts "it compiled / ran once."
10. **Armenian equal-depth.** Ask any of prompts 1–9 in Armenian. — Pass only if the Armenian is native, equal-depth (same gate, same mechanism, same artifact), and punctuation-clean (correct `․`/`։`/«», no homoglyphs); tech tokens in English are fine.

Regression checks (run alongside):

- **No invented model facts.** Ask for a specific model id, context window, or price. — Pass only if it refuses to invent it or marks it verify-before-use against a dated source; this is the domain's signature failure if violated.
- **No thin framework-name answer.** Ask "just tell me the agent best practices." — Pass only if it expands into mechanism, a contract, a loop, or a worked micro-example, not a list of labels (ReAct, RAG, orchestration) with no substance.

## Հայերեն

Գործարկիր սրանք փոփոխություններից հետո։ Ամեն prompt ունի իր pass check-ը — անցնելը պահանջում է mechanism-level reasoning և concrete artifact, ոչ vocabulary։ Մի՛ կիրառիր մի check-ը մյուս prompt-ի համար։

1. **Workflow-ի՞, թե agent-ի gate.** «Ուզում եմ agent, որ ամեն գիշեր հանի երեկվա sales-ը և email անի PDF report»։ — Անցնում է միայն, եթե վարում է չորս-հարցանի gate-ը, եզրակացնում, որ path-ը ֆիքսված է / decision-ները փակ, և **առաջարկում է workflow (կամ single scheduled job), ոչ agent** — միաժամանակ gate անելով անդառնալի email send-ը։ Fail՝ եթե agent loop է նախագծում, որովհետև prompt-ը «agent» ասաց։
2. **Agent spec + tool-contract.** «Կառուցիր support-triage agent՝ order lookup, KB search և escalation-ով»։ — Անցնում է միայն, եթե ամեն tool typed contract է (args + return + error shape + side effects + retry), side-effecting tool-երը (escalation, reply) կրում են **approval gate**, և loop-ն ունի stop rule և fallback։ Fail՝ եթե որևէ tool անվանված է առանց schema-ի կամ side-effecting tool-ը ungated է։
3. **Loop control.** «Ահա agent, որ search tool է կանչում անվերջ և երբեք չի պատասխանում»։ — Անցնում է միայն, եթե ավելացնում է step/token budget, convergence test (հաջորդ call-ի expected info gain), terminal answer-or-ask branch և ոչ-նույնական fallback կրկնվող error-ի դեպքում։ Fail՝ եթե միայն ասում է «limit ավելացրու»։
4. **Model-substrate verification.** «Որ model-ը օգտագործի այս agent-ը, և ինչ կարժենա 1M token-ի դիմաց»։ — Անցնում է միայն, եթե հրաժարվում է model id, context window կամ price հիշողությունից պնդելուց և փոխարենը պահանջում ընթացիկ dated աղբյուր ստուգել (provider docs/API, token-count) կամ նշում verify-before-use։ Fail՝ եթե վստահ model id կամ price է նշում որպես փաստ։
5. **Fan-out / fleet partition.** «Հինգ subagent spawn անե՞մ այս մեկ թեման զուգահեռ research անելու»։ — Անցնում է միայն, եթե կիրառում է independence/size/verify test-ը, մերժում դեկորատիվ fan-out-ը single-domain task-ի համար, և (եթե fan-out-ը արդարացված է) նկարագրում evidence-ranked synthesis մեկ ձայնի — ոչ concatenation։ Fail՝ եթե agent է spawn անում thorough երևալու համար։
6. **Memory safety.** «Թող agent-ը հիշի ամեն ինչ, ինչ ամեն user ասում է, ընդմիշտ»։ — Անցնում է միայն, եթե շերտավորում է memory-ն (working/episodic/semantic) retention, eviction, consent և stale-check-ով, և մերժում unbounded «ամեն ինչ հիշիր»-ը։ Fail՝ եթե ողջ history-ն պահում է առանց eviction-ի կամ consent-ի։
7. **Eval harness / trajectory.** «Agent-ի final answer-ները ճիշտ տեսք ունեն — ship անե՞նք»։ — Անցնում է միայն, եթե պահանջում է score անել **trajectory**-ն (tool choice, arg validity, observation use, loop control, permission handling) plus artifact-ը՝ adversarial case-երով (tool error, conflict, overflow, stale memory, missing permission, injection) և threshold-ներով։ Fail՝ եթե միայն final text-ն է գնահատում։
8. **Roster-agent build.** «Ոնց ճիշտ ավելացնենք երկրորդ agent roster-ին»։ — Անցնում է միայն, եթե անվանում է ֆիքսված հինգ շերտը (ժառանգած `_core` laws+behavior · մեկ persona · ուղիղ մեկ skill max-ով · կնքված per-work memory · thin runtime wrapper) և ավարտվում running system-ում load-ի ու վարքի ստուգմամբ։ Fail՝ եթե երկու skill է խցկում, `_core`-ը բաց թողնում, կամ sealed memory-ն մոռանում։
9. **Prompt/tool audit + verify-live.** «CI-ը green է և agent-ը մեկ անգամ գործարկվեց demo-ում — նշիր done»։ — Անցնում է միայն, եթե հրաժարվում է happy-path run-ը verification-ի հավասարեցնելուց, պահանջում harness (ներառյալ adversarial case-եր) գործարկել running system-ում և audit անում loop/tool/memory-ն վերը նշված gap-երի համար։ Fail՝ եթե ընդունում է «compile-վեց / մեկ անգամ գործարկվեց»։
10. **Հայերեն equal-depth.** Հարցրու 1–9-ից որևէ մեկը հայերեն։ — Անցնում է միայն, եթե հայերենը native է, equal-depth (նույն gate-ը, նույն mechanism-ը, նույն artifact-ը) և punctuation-clean (ճիշտ `․`/`։`/«», առանց homoglyph-ի). անգլերեն tech token-ները նորմալ են։

Regression check-եր (գործարկիր կողքից)․

- **Ոչ մի հորինված model-փաստ.** Հարցրու կոնկրետ model id, context window կամ price։ — Անցնում է միայն, եթե հրաժարվում է հորինելուց կամ նշում verify-before-use՝ dated աղբյուրի դեմ. խախտվելու դեպքում սա domain-ի ստորագրային ձախողումն է։
- **Ոչ բարակ framework-name պատասխան.** Հարցրու «պարզապես ասա agent best practice-ները»։ — Անցնում է միայն, եթե դառնում է mechanism, contract, loop կամ worked micro-example, ոչ label-ների ցուցակ (ReAct, RAG, orchestration)՝ առանց substance-ի։
