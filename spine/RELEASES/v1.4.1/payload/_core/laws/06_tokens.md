# 06 — ZERO HARDCODE / TOKEN-BASED LAW

L13 — ZERO HARDCODE · EVERYTHING TOKEN-BASED (Gev amendment 2026-07-02, per D0) · ALL AGENTS INHERIT

EN: Anything any agent builds carries ZERO hardcoded values — everything resolves through TOKENS. Two pillars, both absolute: **(1) DESIGN** — every design value (color, spacing, size, radius, typography, shadow, z-index, motion, breakpoint) comes from a DESIGN TOKEN, never a literal; **(2) LANGUAGE** — every user-facing string comes from an I18N / LANGUAGE TOKEN (a translation key), never inline copy. There is ONE source of truth per token, referenced everywhere. Switching the theme OR the language MUST require no code change and MUST leave NOTHING un-themed or un-translated — no string escapes translation, no value escapes theming. No magic numbers, no inline strings, no baked-in config a token could carry. This is a build-time GATE, not a preference: a hardcoded design value or a user-facing literal is a DEFECT — flag it, tokenize it. Bro holds itself AND every agent it dispatches to this standard, on everything they build.

HY: Ամեն ինչ, որ որևէ agent կառուցում է, կրում է ԶՐՈ hardcode արժեք — ամեն ինչ լուծվում է ՏՈԿԵՆՆԵՐՈՎ։ Երկու հիմնասյուն, երկուսն էլ բացարձակ՝ **(1) ԴԻԶԱՅՆ** — ամեն դիզայնի արժեք (գույն, spacing, չափ, radius, տառատեսակ, shadow, z-index, motion, breakpoint) գալիս է DESIGN token-ից, ոչ երբեք literal-ից. **(2) ԼԵԶՈՒ** — ամեն user-facing string գալիս է I18N / լեզվի token-ից (translation key), ոչ երբեք inline տեքստից։ Ամեն token-ի համար՝ ՄԵԿ ճշմարտության աղբյուր, հղվում ամենուր։ Theme-ը ԿԱՄ լեզուն փոխելը ՊԵՏՔ Է չպահանջի կոդի փոփոխություն ու ՊԵՏՔ Է ոչինչ չթողնի առանց theme-ի կամ առանց թարգմանության — ոչ մի string չփախչի թարգմանությունից, ոչ մի արժեք չփախչի theming-ից։ Ոչ magic number, ոչ inline string, ոչ baked-in config, որ token-ը կարող էր կրել։ Սա build-time ԴԱՐՊԱՍ է, ոչ նախապատվություն. hardcode արած դիզայնի արժեքը կամ user-facing literal-ը ԴԵՖԵԿՏ է — flag արա, token դարձրու։ Bro-ն ԻՐԵՆ ու ամեն dispatch արած agent-ին պահում է այս չափանիշով՝ ամեն ինչում, որ կառուցում են։

Enforcement / Կիրառում — EN: Before shipping any build, scan for hardcoded design values and user-facing literals; each is a defect that must become a token. A theme or language switch must be provably complete — nothing left behind. New strings and values land as tokens from the FIRST commit, never retrofitted later. · HY: Ցանկացած build թողարկելուց առաջ scan արա hardcode արած դիզայնի արժեքների ու user-facing literal-ների համար. ամեն մեկը դեֆեկտ է, որ պիտի token դառնա։ Theme-ի կամ լեզվի փոխանջատումը պիտի ապացուցելիորեն ամբողջական լինի — ոչինչ ետևում չմնա։ Նոր string-ներն ու արժեքները ԱՌԱՋԻՆ commit-ից token են, ոչ թե հետո retrofit արվեն։

> **Cross-ref / Cross-ref:** L0 (bilingual) — both languages are themselves delivered through language tokens, so bilingual parity survives ANY language switch; L13 makes design + language both fully tokenized, single-source, swap-safe. **HY:** L0 (երկլեզու) — երկու լեզուն էլ մատուցվում են լեզվի token-ներով, ուստի երկլեզու parity-ն վերապրում է ցանկացած language switch. L13-ը դիզայնն ու լեզուն դարձնում է լիովին tokenized, single-source, swap-safe։
