# Telecom, ISP, and Network Operations manual

## English

### Operating principle

Senior telecom, ISP, and network operations work is decision-grade only when a connectivity change cannot quietly become an outage, and when every customer-facing number traces to a measurement instead of a claim. The deliverable is one of a few shapes: an outage triage, a change MOP (method of procedure), a BGP/route-risk review, a PON optical-budget sheet, a BNG/subscriber-fault diagnosis, or an SLA/availability report. The single guardrail that governs all of them is reversibility under observation: no change ships without a rollback trigger and a validation that reads the running network, and no diagnosis jumps layers — it descends the stack from physical reality (light, power, alarms, the last change) up to the application, because the cheapest fix is almost always below where the symptom is felt. Reliability here is not the absence of faults; it is faults caught at the layer they live on, contained inside a change window, and reported to the customer with the real downtime, not an apology.

### Mechanism reference

- **Layered network triage (OSI, pragmatically).** Descend the stack in order: physical (optical Rx/Tx power, power, fiber cut, OLT alarms) → data link (link errors, CRC, flap, VLAN/MPLS label) → network (IP reachability, ARP/ND, MTU) → routing (BGP/OSPF/IS-IS adjacency, route presence) → DNS/application. Always open with blast radius (how many, where, which shared element) and the last change, because most outages are change-induced and most physical faults are mis-diagnosed upward. Do not debug BGP when the OLT shows loss-of-signal; do not replace a CPE when the splitter is the fault.
- **PON access and optical budget.** A PON (GPON/XGS-PON) OLT feeds many ONU/ONT units over a passive split. Service degrades from optical budget exhaustion, an over-large split ratio, distance, dirty/broken connectors, bends, or a rogue ONU transmitting out of its slot. The **GPON optical loss budget is set by class: Class B+ = 28 dB (13–28 dB), Class C+ = 32 dB (17–32 dB)**. Budget is consumed by splitter insertion loss (a 1:32 split ≈ 17–18 dB, 1:64 ≈ 20–21 dB), fiber attenuation (~0.3–0.35 dB/km at 1310 nm), connectors, and splices — sum the per-element loss and keep margin under the class budget. **A standard residential split is 1:32 or 1:64; 1:128 is not a standard residential GPON split — its splitter loss alone pushes total loss past the B+ 28 dB budget, so it needs higher-class optics (C+) or a reach extender/amplification.** Read Rx power and OLT alarms before dispatching a truck; correlated low Rx across many ONUs is shared plant, not a bad ONT.
- **BGP routing safety and the MOP.** A route change is safe only with: prefix filters (announce by intent — customer/peer/transit, never leak one class to another), max-prefix on every session (caps a leak/flood), communities and local-pref/MED to express path intent, an **expected post-change route-count** to validate against, validation commands, monitoring, a rollback trigger, and customer/peer comms. A **route leak** is an over-broad export (e.g. re-announcing a peer's routes to transit); a **blackhole** is an unreachable next-hop or a withdrawn needed prefix. RPKI Route Origin Validation expresses which AS may originate a prefix and should inform (not silently override) policy. The MOP shape is constant: pre-check (capture current state) → change → validation (compare to expected) → rollback trigger (named condition + tested command) → comms.
- **BNG/BRAS and the subscriber edge.** The Broadband Network Gateway / Broadband Remote Access Server terminates subscriber sessions at the edge and applies policy (rate, QoS, ACL). Two session models: **PPPoE** (LCP → authentication (PAP/CHAP) → IPCP, an explicit session with discovery/keepalive) and **IPoE** (DHCP with option-82 line-id, no PPP session, identity keyed on circuit/MAC). The BNG is a **RADIUS client**: Access-Request → Access-Accept/Reject for auth/authz, and Accounting Start/Interim/Stop for session usage. A **mid-session policy change** (new rate, walled-garden, forced logout) is pushed by RADIUS **CoA (Change of Authorization)** or **Disconnect-Message**, not a re-auth. **Wholesale/open-access**: the access provider can hand the session to a retail ISP's BNG via **L2TP (LAC→LNS)** so the subscriber authenticates against the retail ISP — the access network is layer-2 transport, the retail ISP owns auth and IP.
- **TR-069 / TR-369 CPE management.** TR-069 (CWMP) is the operator↔CPE management protocol: the CPE talks to an **ACS (Auto Configuration Server)** over a SOAP/HTTP session, exposing a **parameter model (data model)** of objects/parameters the ACS reads/writes (GetParameterValues/SetParameterValues), plus Download for firmware and a connection-request to reach the CPE. A **firmware campaign** is staged: validate the image, push to a **canary cohort**, watch failure/return rates, expand by rings, and **halt-on-failure** with a rollback image — never a blind fleet-wide push. **TR-369 (USP)** is the successor: a **controller/agent** model with multiple transports (MQTT, WebSocket, STOMP, CoAP), richer data model and operations, designed for scale and for non-HTTP-friendly devices; the staged-rollout discipline is identical.
- **Mediation and CDR/rating.** Mediation sits between network elements and billing. It collects **CDRs (Call/Charging Detail Records)**, then: **de-duplicates** (network elements emit overlapping records; dedup on a stable record key prevents double-billing), **normalizes** (unify formats, time zones, units, and field semantics across vendor element types), correlates partial records into one session, filters/enriches, and only then hands clean records to rating. **Roaming** uses **TAP3** (Transferred Account Procedure v3), an **ASN.1**-encoded inter-operator record format — handle/validate TAP3 before rating roaming usage. Two rating paths: **OCS (Online Charging System)** via Diameter **Gy** does real-time, **balance-aware** credit-control (reserve/grant/debit, can cut off at zero) for prepaid/quota; **offline batch rating** processes CDRs after the fact for postpaid. Choose OCS when a balance must be enforced live, batch when it need not.
- **Lawful intercept (operational interface only).** Lawful intercept is the legally mandated, warrant-authorized handover of a target's communications/metadata to an authorized agency. Operationally it has two streams — **IRI (intercept-related information / metadata)** and **CC (call/content)** — delivered to a mediation/handover function under a standardized interface (e.g. ETSI handover). **The operations role is execution under a validated lawful order, never design-on-request:** the warrant's legality and scope are owned by legal and the issuing authority; operations provisions only an intercept that arrives through the documented lawful channel, with an audit trail, minimized to the order's scope, and access-controlled. Any tap/log/expose request without that validated, authorized order is refused and routed to legal/the responsible authority. This is the hard gate of the skill.
- **SLA and availability math.** Availability = uptime / total measured time, with **excluded (scheduled) maintenance** removed from the denominator only if the contract says so. **99.9% monthly ≈ 43.2 minutes** of allowed downtime (0.1% of 43,200 min), **99.99% ≈ 4.32 minutes**, **99.95% ≈ 21.6 minutes**. Keep availability, latency, packet loss, jitter, and MTTR as **separate** metrics — a link can be "available" and still unusable on loss/jitter. A customer incident report needs the measured downtime window, affected services, root cause as contributing factors, remediation, and prevention — not just an apology, and never an invented credit or statute.

### Decision rules

1. On any outage, fix blast radius and the last change first, then descend the OSI stack from physical up; do not debug routing when the physical layer is alarming.
2. When many subscribers on one OLT/PON degrade together, suspect shared plant (splitter/feeder/connector/OLT port), read Rx power before dispatch, and do not swap CPE on a shared-symptom fault.
3. Measure optical loss against the class budget (B+ = 28 dB) with a per-element loss table; flag 1:128 as non-standard for residential and require higher-class optics or a reach extender.
4. Ship no routing change without a MOP: prefix filters, max-prefix, communities/local-pref/MED intent, an expected route-count, validation, monitoring, a rollback trigger, and comms.
5. Filter announcements by intent and apply max-prefix to prevent leaks; verify next-hop reachability to prevent blackholes; treat both as policy errors to design out.
6. For a subscriber that cannot connect, identify PPPoE vs IPoE, trace the RADIUS exchange (Access-Request/Accept/Reject, accounting), and use CoA/Disconnect for live policy changes — not a core reboot.
7. Drive CPE config/firmware through the ACS (TR-069/TR-369) in a staged campaign (canary → rings → halt-on-failure with a rollback image); never a blind mass push.
8. In mediation, dedup and normalize before rating, correlate partials, handle TAP3 for roaming, and choose OCS (live balance) vs batch rating by whether a balance must be enforced in real time.
9. Convert any SLA stated as a feeling into availability minutes (99.9% ≈ 43.2 min) and keep availability/latency/loss/jitter/MTTR separate with maintenance exclusions stated.
10. Size capacity and peering on the 95th-percentile and the loss/latency-under-load curve, not the average; tie every upgrade to measured utilization and a cost-per-Mbps, and choose transit/peering/IXP on ratio and cost.
11. Respect change-freeze windows, schedule inside the maintenance window, pre-notify affected customers, and name the rollback trigger before the first command.
12. Gate any lawful-intercept or subscriber-data-exposure request on a validated lawful order with an audit trail; absent that, refuse and route to legal/the responsible authority.
13. Gate irreversible/core-impacting changes (core swap, gateway move, mass CPE push, region-dropping changes) behind explicit human approval with the rollback named first.
14. Never treat a clean parse or a green lab as verification; observe the running network — route-count, Rx, session count, SLA metric — before declaring the change done.

### Failure-repair playbook

1. **Triage jumped to the app layer while physical is alarming** → stop, read the optical levels and OLT/link alarms, re-anchor at the lowest alarming layer, and confirm blast radius and last change before going up.
2. **CPE being swapped on a shared-plant symptom** → halt the truck rolls, pull Rx power for the whole PON, and if many ONUs are low, inspect splitter/feeder/connector/OLT port — replace shared plant, not customer ONTs.
3. **Optical design has no per-element loss table** → build the budget: splitter loss + fiber attenuation × distance + connectors + splices, compare to the class budget (B+ = 28 dB), add margin, and re-class or re-design if a 1:128 split blew the budget.
4. **Routing change has no MOP / no expected route-count** → it is not a change plan yet; capture current state, define the expected post-change route-count and reachability, add validation, monitoring, a rollback trigger, and comms before touching the session.
5. **Session has no prefix filter or max-prefix** → add intent-based prefix filters and a max-prefix cap immediately; treat the gap as a standing leak/flood risk and re-validate the announced route-count.
6. **Blackhole after a policy push** → compare live route-count and reachability to the expected post-state, find the unreachable next-hop or wrongly-withdrawn prefix, fire the rollback trigger, then redo the change with the next-hop check in validation.
7. **Subscriber fault being "fixed" by core changes** → stop core churn; identify PPPoE vs IPoE, read the Access-Reject reason or the accounting gap, and if it is a live policy issue use CoA/Disconnect rather than re-auth or reboot.
8. **Mass firmware push with no canary** → halt the campaign, define a canary cohort and a failure threshold, stage by rings with a rollback image, and only resume through the ACS with halt-on-failure armed.
9. **Mediation rating raw or duplicated CDRs** → insert dedup (stable record key) and normalization before rating, correlate partial records, validate TAP3 for roaming, and re-rate the affected window to correct the bills.
10. **SLA report is an apology** → add the measured downtime window, the availability math (uptime/measured-time with stated exclusions), affected services, contributing-factor root cause, and prevention; remove any invented credit or statute.
11. **Capacity sized on averages** → re-size against the 95th-percentile and the loss/latency-under-load curve, attach measured utilization and a cost-per-Mbps, and decide transit vs peering vs IXP on traffic ratio.
12. **Intercept/exposure requested with no lawful order** → refuse, do not provision, and route the request to legal/the responsible authority; provision only an intercept that arrives through the documented lawful channel with an audit trail, minimized to scope.

### BNG/BRAS deep section (PPPoE vs IPoE, RADIUS, CoA, wholesale)

PPPoE builds an explicit session — PPPoE discovery (PADI/PADO/PADR/PADS) → LCP → authentication (PAP/CHAP, RADIUS-checked) → IPCP for the address — and is easy to account and tear down but adds an 8-byte overhead and keepalive load. IPoE has no PPP session: identity is keyed on DHCP option-82 (circuit/remote-id inserted by the access node) or the MAC/VLAN, the BNG snoops/relays DHCP and applies RADIUS-returned policy, lower overhead but identity hygiene depends on the access layer inserting trustworthy option-82. In both, the **BNG is a RADIUS client**: Access-Request carries the subscriber identity, Access-Accept returns the policy (rate-limit, VRF, framed-IP, filter-id), Access-Reject carries a reason worth reading before blaming the core; Accounting Start/Interim/Stop drives usage and the mediation feed. A **live policy change** — speed change after a top-up, move to a walled garden for non-payment, force a re-login — is a **CoA** (modify) or **Disconnect-Message** (drop), so you do not wait for the next login. **Wholesale/open-access** uses **L2TP**: the access provider's LAC tunnels the session to the retail ISP's LNS, so the subscriber authenticates against the retail ISP's RADIUS and gets the retail ISP's IP — the access network is pure layer-2 transport and owns none of the auth.

### TR-069 / TR-369 deep section (ACS, parameter model, firmware flow)

TR-069 (CWMP) connects the CPE to an **ACS** over SOAP/HTTP. The CPE exposes a **parameter model**: a tree of objects and parameters (device info, WAN/LAN config, Wi-Fi, diagnostics) the ACS reads with GetParameterValues and writes with SetParameterValues; the ACS reaches an idle CPE with a connection-request, and the CPE Informs the ACS on boot/value-change/scheduled. **Firmware flow:** stage the image on a download server, instruct the cohort to Download and apply, watch the post-apply Inform and the return/failure rate, expand by rings, and halt-on-failure with a known-good rollback image — a canary cohort first, never the whole fleet at once. **TR-369 (USP)** generalizes this to a **controller/agent** architecture with pluggable transports (MQTT, WebSocket, STOMP, CoAP) and a richer data model and operation set, built for scale, NAT-friendliness, and non-HTTP devices; the operational discipline — staged rollout, canary, halt-on-failure, rollback image — is unchanged.

### Mediation / CDR deep section (dedup, normalization, ASN.1/TAP3)

Mediation turns raw network records into clean, billable, deduplicated, normalized records. **Dedup:** network elements emit overlapping CDRs (the same event seen by two nodes); dedup on a stable record key (element-id + sequence + timestamp window) prevents double-billing — rating a raw, undeduped feed is a revenue bug. **Normalization:** unify field formats, time zones, units, and semantics across heterogeneous vendor elements so rating sees one schema, and correlate partial records (long sessions split across files) into one usage event. **ASN.1/TAP3:** roaming usage is exchanged between operators as **TAP3** records, **ASN.1**-encoded; decode and validate the TAP3 file (and reject/RAP-return malformed ones) before rating roaming. Only after dedup + normalization + correlation do records reach rating: **OCS** (Diameter Gy) for real-time, balance-aware credit-control, or **offline batch** for postpaid CDR rating.

### Lawful intercept deep section (operational, gated)

Lawful intercept is the warrant-authorized handover of a target's communications to an authorized agency, with two streams — **IRI** (intercept-related information / metadata: who, when, where) and **CC** (call content) — delivered through a mediation/handover function over a standardized interface (e.g. ETSI handover). **The skill's role is execution under a validated lawful order, with strict scope and audit, never design-on-request.** Operations: (1) accepts an intercept only through the documented lawful channel with the order on file; (2) minimizes to the order's target and time scope; (3) keeps an audit trail and tight access control; (4) routes any question of legality, validity, or scope to legal and the issuing authority. A request to tap, log, mirror, or expose a subscriber without that validated order — however it is phrased — is refused and routed to legal. This is the inline hard gate; `red-team-gate.md` only extends it.

### Verify live, not a clean parse

A config that parses and a lab that is green are necessary, not sufficient. Before calling a change done, observe the running network: read the real route-count against the expected post-state, the real Rx power on the affected PON, the real session count on the BNG, the real availability/latency/loss on the SLA metric, the real firmware-return rate on the campaign. Treating a clean parse or a green lab as "verified" is how a change that compiled still drops a region or doubles a bill.

## Հայերեն

### Գործառնական սկզբունք

Ավագ telecom, ISP և network operations աշխատանքը decision-grade է միայն այն ժամանակ, երբ connectivity change-ը չի կարող լուռ outage դառնալ, և երբ ամեն customer-facing թիվ հետ է գնում չափման, ոչ պնդման։ Deliverable-ը մի քանի ձևից մեկն է՝ outage triage, change MOP (method of procedure), BGP/route-risk review, PON optical-budget sheet, BNG/subscriber-fault diagnosis կամ SLA/availability report։ Բոլորը կառավարող միակ guardrail-ը observation-ի տակ հետշրջելիությունն է․ ոչ մի change չի ship-վում առանց rollback trigger-ի և validation-ի, որ կարդում է running network-ը, և ոչ մի diagnosis շերտ չի ցատկում — այն իջնում է stack-ով physical իրականությունից (light, power, alarm, last change) մինչև application, որովհետև ամենաէժան fix-ը գրեթե միշտ ավելի ցածր է, քան symptom-ը զգացվում է։ Հուսալիությունն այստեղ fault-ների բացակայությունը չէ. այն fault է՝ բռնված այն շերտում, որտեղ ապրում է, պահված change window-ի ներսում, և customer-ին report-ված իրական downtime-ով, ոչ apology-ով։

- **BNG/BRAS և subscriber edge-ը։** Broadband Network Gateway / Broadband Remote Access Server-ը edge-ում terminate է անում subscriber session-ները և կիրառում policy (rate, QoS, ACL)։ Երկու session model․ **PPPoE** (LCP → authentication (PAP/CHAP) → IPCP, բացահայտ session՝ discovery/keepalive-ով) և **IPoE** (DHCP՝ option-82 line-id-ով, ոչ PPP session, identity-ն keyed circuit/MAC-ով)։ BNG-ն **RADIUS client** է․ Access-Request → Access-Accept/Reject՝ auth/authz-ի համար, և Accounting Start/Interim/Stop՝ session usage-ի համար։ **Mid-session policy change**-ը (նոր rate, walled-garden, force logout) push է լինում RADIUS **CoA (Change of Authorization)**-ով կամ **Disconnect-Message**-ով, ոչ re-auth-ով։ **Wholesale/open-access**․ access provider-ը կարող է session-ը հանձնել retail ISP-ի BNG-ին **L2TP (LAC→LNS)**-ով, որ subscriber-ը authenticate անի retail ISP-ի դեմ — access network-ը layer-2 transport է, retail ISP-ն տիրում է auth-ին և IP-ին։
- **TR-069 / TR-369 CPE management։** TR-069 (CWMP)-ն operator↔CPE management protocol է․ CPE-ն խոսում է **ACS (Auto Configuration Server)**-ի հետ SOAP/HTTP session-ով, բացահայտելով **parameter model (data model)**՝ object-ների/parameter-ների, որ ACS-ը կարդում/գրում է (GetParameterValues/SetParameterValues), plus Download firmware-ի համար և connection-request CPE-ին հասնելու։ **Firmware campaign**-ը staged է․ validate արա image-ը, push արա **canary cohort**-ին, հետևիր failure/return rate-ին, ընդլայնիր ring-երով, և halt-on-failure արա rollback image-ով — երբեք կույր fleet-wide push։ **TR-369 (USP)**-ն հաջորդն է․ **controller/agent** model՝ բազմաթիվ transport-ով (MQTT, WebSocket, STOMP, CoAP), ավելի հարուստ data model և operation, նախագծված scale-ի և non-HTTP-friendly device-ների համար. staged-rollout-ի կարգապահությունը նույնն է։
- **Mediation և CDR/rating։** Mediation-ը նստած է network element-ների և billing-ի միջև։ Այն հավաքում է **CDR (Call/Charging Detail Record)**, հետո․ **de-dup** է անում (network element-ները overlapping record են արձակում. dedup՝ stable record key-ով, կանխում է double-billing-ը), **normalize** է անում (միավորում format-ը, time zone-ը, unit-ը և field semantics-ը vendor element-ների միջև), correlate է անում partial record-ները մեկ session-ի, filter/enrich, և միայն դրանից հետո հանձնում մաքուր record-ները rating-ին։ **Roaming**-ը օգտագործում է **TAP3** (Transferred Account Procedure v3), **ASN.1**-encoded inter-operator record format — handle/validate արա TAP3-ը մինչև roaming usage-ը rate անելը։ Երկու rating path․ **OCS (Online Charging System)** Diameter **Gy**-ով անում է real-time, **balance-aware** credit-control (reserve/grant/debit, կարող է զրոյին կտրել) prepaid/quota-ի համար. **offline batch rating**-ը մշակում է CDR-ները հետո՝ postpaid-ի համար։ Ընտրիր OCS, երբ balance-ը պետք է live enforce-վի, batch՝ երբ ոչ։
- **Lawful intercept (միայն օպերացիոն interface)։** Lawful intercept-ը target-ի communication-ի/metadata-ի օրինականորեն պարտադրված, warrant-լիազորված handover-ն է authorized agency-ին։ Օպերացիոն առումով այն ունի երկու stream — **IRI (intercept-related information / metadata)** և **CC (call/content)** — հանձնված mediation/handover function-ին standardized interface-ով (օր.՝ ETSI handover)։ **Operations-ի դերը վավերացված օրինական order-ի տակ կատարումն է, երբեք design-on-request չէ․** warrant-ի օրինականությունն ու scope-ը legal-ինն ու order տվող իշխանությանն են. operations-ը provision է անում միայն intercept, որ գալիս է փաստաթղթավորված օրինական channel-ով՝ audit trail-ով, minimize-ված order-ի scope-ին, և access-controlled։ Subscriber-ին tap/log/expose անելու ցանկացած հարցում՝ առանց այդ վավերացված, լիազորված order-ի, մերժվում է և ուղղորդվում legal-ին/պատասխանատու իշխանությանը։ Սա skill-ի hard gate-ն է։
- **SLA և availability math։** Availability = uptime / total measured time, **excluded (scheduled) maintenance**-ը հանված denominator-ից միայն, եթե contract-ն այդպես է ասում։ **99.9% monthly ≈ 43.2 minute** թույլատրելի downtime (43,200 min-ի 0.1%-ը), **99.99% ≈ 4.32 minute**, **99.95% ≈ 21.6 minute**։ Պահիր availability, latency, packet loss, jitter և MTTR որպես **առանձին** metric — link-ը կարող է «available» լինել և դեռ անօգտագործելի loss/jitter-ով։ Customer incident report-ը պետք է ունենա չափված downtime window, ազդակիր service-ներ, root cause որպես contributing factor, remediation և prevention — ոչ պարզապես apology, և երբեք հորինված credit կամ statute։

### Որոշման կանոններ

1. Ցանկացած outage-ի դեպքում ֆիքսիր blast radius-ը և last change-ը նախ, հետո իջիր OSI stack-ով physical-ից վեր. routing մի՛ debug արա, երբ physical layer-ը alarm է անում։
2. Երբ մեկ OLT/PON-ի շատ subscriber միասին degrade են անում, կասկածիր shared plant (splitter/feeder/connector/OLT port), կարդա Rx power-ը dispatch-ից առաջ, և shared-symptom fault-ի վրա CPE մի՛ փոխիր։
3. Չափիր optical loss-ը class budget-ի դեմ (B+ = 28 dB)՝ per-element loss table-ով. flag արա 1:128-ը որպես residential-ի համար ոչ-standard և պահանջիր ավելի բարձր class-ի optics կամ reach extender։
4. Ոչ մի routing change մի՛ ship արա առանց MOP-ի․ prefix filter, max-prefix, communities/local-pref/MED intent, expected route-count, validation, monitoring, rollback trigger և comms։
5. Filter արա announcement-ները ըստ intent-ի և կիրառիր max-prefix՝ leak կանխելու. ստուգիր next-hop reachability՝ blackhole կանխելու. երկուսն էլ համարիր policy սխալ, որ պետք է design-out անել։
6. Subscriber-ի համար, որ չի կարողանում connect անել, նույնականացրու PPPoE ընդդեմ IPoE, trace արա RADIUS exchange-ը (Access-Request/Accept/Reject, accounting), և live policy change-ի համար օգտագործիր CoA/Disconnect — ոչ core reboot։
7. Վարիր CPE config/firmware-ը ACS-ով (TR-069/TR-369) staged campaign-ով (canary → ring-եր → halt-on-failure՝ rollback image-ով). երբեք կույր mass push։
8. Mediation-ում dedup և normalize արա rating-ից առաջ, correlate արա partial-ները, handle արա TAP3 roaming-ի համար, և ընտրիր OCS (live balance) ընդդեմ batch rating-ի՝ ըստ նրա, balance-ը պետք է real time-ում enforce-վի՞։
9. Զգացմունքով ասված ցանկացած SLA վերածիր availability minute-ի (99.9% ≈ 43.2 min) և պահիր availability/latency/loss/jitter/MTTR առանձին՝ maintenance exclusion-ները նշված։
10. Size արա capacity-ն և peering-ը 95-րդ percentile-ով և load-ի տակ loss/latency curve-ով, ոչ average-ով. ամեն upgrade կապիր չափված utilization-ի և cost-per-Mbps-ի հետ, և ընտրիր transit/peering/IXP՝ ratio-ով և cost-ով։
11. Հարգիր change-freeze window-ները, ժամանակացրու maintenance window-ի ներսում, նախ-notify արա ազդակիր customer-ներին, և անվանի՛ր rollback trigger-ը մինչև առաջին command-ը։
12. Gate արա ցանկացած lawful-intercept կամ subscriber-data-exposure հարցում վավերացված օրինական order-ի վրա՝ audit trail-ով. դրա բացակայության դեպքում մերժիր և ուղղորդիր legal-ին/պատասխանատու իշխանությանը։
13. Gate արա անդառնալի/core-impacting change-երը (core swap, gateway տեղափոխում, mass CPE push, region-գցող change) հստակ մարդկային approval-ի հետևում՝ rollback-ը նախ անվանված։
14. Երբեք մաքուր parse-ը կամ green lab-ը verification մի՛ համարիր. դիտիր running network-ը — route-count, Rx, session count, SLA metric — մինչև change-ը done հայտարարելը։

### Վերականգնման խաղագիրք

1. **Triage-ն ցատկեց app layer, մինչ physical-ը alarm է** → կանգնիր, կարդա optical level-ները և OLT/link alarm-ները, re-anchor արա ամենացածր alarm-ող շերտում, և հաստատիր blast radius-ն ու last change-ը մինչև վեր գնալը։
2. **CPE-ն փոխվում է shared-plant symptom-ի վրա** → կանգնեցրու truck roll-երը, քաշիր Rx power-ը ողջ PON-ի համար, և եթե շատ ONU low են, ստուգիր splitter/feeder/connector/OLT port — փոխիր shared plant-ը, ոչ customer ONT-ները։
3. **Optical design-ը per-element loss table չունի** → կառուցիր budget-ը․ splitter loss + fiber attenuation × distance + connector + splice, համեմատիր class budget-ի հետ (B+ = 28 dB), ավելացրու margin, և re-class կամ re-design արա, եթե 1:128 split-ը budget-ը պայթեցրեց։
4. **Routing change-ը MOP / expected route-count չունի** → այն դեռ change plan չէ. capture արա current state-ը, սահմանիր սպասվող post-change route-count-ը և reachability-ն, ավելացրու validation, monitoring, rollback trigger և comms մինչև session-ին դիպչելը։
5. **Session-ը prefix filter կամ max-prefix չունի** → ավելացրու intent-based prefix filter և max-prefix cap անմիջապես. համարիր բացը մշտական leak/flood risk և re-validate արա announce արված route-count-ը։
6. **Blackhole policy push-ից հետո** → համեմատիր live route-count-ը և reachability-ն expected post-state-ի հետ, գտիր unreachable next-hop-ը կամ սխալ-withdraw արված prefix-ը, կրակիր rollback trigger-ը, հետո վերարա change-ը validation-ում next-hop check-ով։
7. **Subscriber fault «ֆիքսվում» է core change-ով** → կանգնեցրու core churn-ը. նույնականացրու PPPoE ընդդեմ IPoE, կարդա Access-Reject reason-ը կամ accounting gap-ը, և եթե live policy խնդիր է, օգտագործիր CoA/Disconnect, ոչ re-auth կամ reboot։
8. **Mass firmware push առանց canary-ի** → կանգնեցրու campaign-ը, սահմանիր canary cohort և failure threshold, stage արա ring-երով rollback image-ով, և վերսկսիր միայն ACS-ով՝ halt-on-failure-ը զինված։
9. **Mediation-ը raw կամ կրկնված CDR է rate անում** → տեղադրիր dedup (stable record key) և normalization rating-ից առաջ, correlate արա partial record-ները, validate արա TAP3 roaming-ի համար, և re-rate արա ազդակիր window-ը bill-երը ուղղելու։
10. **SLA report-ը apology է** → ավելացրու չափված downtime window-ը, availability math-ը (uptime/measured-time՝ նշված exclusion-ներով), ազդակիր service-ները, contributing-factor root cause-ը և prevention-ը. հեռացրու ցանկացած հորինված credit կամ statute։
11. **Capacity-ն size-ված average-ով** → re-size արա 95-րդ percentile-ի և load-ի տակ loss/latency curve-ի դեմ, կցիր չափված utilization և cost-per-Mbps, և որոշիր transit ընդդեմ peering-ի՝ traffic ratio-ով։
12. **Intercept/exposure խնդրված առանց օրինական order-ի** → մերժիր, մի՛ provision արա, և ուղղորդիր հարցումը legal-ին/պատասխանատու իշխանությանը. provision արա միայն intercept, որ գալիս է փաստաթղթավորված օրինական channel-ով՝ audit trail-ով, minimize-ված scope-ին։

### BNG/BRAS խորը բաժին (PPPoE ընդդեմ IPoE, RADIUS, CoA, wholesale)

PPPoE-ն կառուցում է բացահայտ session — PPPoE discovery (PADI/PADO/PADR/PADS) → LCP → authentication (PAP/CHAP, RADIUS-checked) → IPCP հասցեի համար — և հեշտ է account և tear down անել, բայց ավելացնում է 8-byte overhead և keepalive load։ IPoE-ն PPP session չունի․ identity-ն keyed է DHCP option-82-ով (circuit/remote-id, որ access node-ն է insert անում) կամ MAC/VLAN-ով, BNG-ն snoop/relay է անում DHCP-ն և կիրառում RADIUS-returned policy, ավելի ցածր overhead, բայց identity hygiene-ը կախված է access layer-ի վստահելի option-82 insert անելուց։ Երկուսում էլ **BNG-ն RADIUS client է**․ Access-Request-ը կրում է subscriber identity-ն, Access-Accept-ը վերադարձնում է policy-ն (rate-limit, VRF, framed-IP, filter-id), Access-Reject-ը կրում է reason, որ արժե կարդալ core-ին մեղադրելուց առաջ. Accounting Start/Interim/Stop-ը driving է usage-ը և mediation feed-ը։ **Live policy change**-ը — speed change top-up-ից հետո, walled garden non-payment-ի համար, force re-login — **CoA** է (modify) կամ **Disconnect-Message** (drop), որ հաջորդ login-ին չսպասես։ **Wholesale/open-access**-ը օգտագործում է **L2TP**․ access provider-ի LAC-ը session-ը tunnel է անում retail ISP-ի LNS-ին, որ subscriber-ը authenticate անի retail ISP-ի RADIUS-ի դեմ և ստանա retail ISP-ի IP — access network-ը մաքուր layer-2 transport է և auth-ի ոչ մի մասին չի տիրում։

### TR-069 / TR-369 խորը բաժին (ACS, parameter model, firmware flow)

TR-069 (CWMP)-ն CPE-ն կապում է **ACS**-ի հետ SOAP/HTTP-ով։ CPE-ն բացահայտում է **parameter model**․ object-ների և parameter-ների ծառ (device info, WAN/LAN config, Wi-Fi, diagnostics), որ ACS-ը կարդում է GetParameterValues-ով և գրում SetParameterValues-ով. ACS-ը idle CPE-ին հասնում է connection-request-ով, և CPE-ն Inform է անում ACS-ին boot/value-change/scheduled-ի վրա։ **Firmware flow․** stage արա image-ը download server-ի վրա, հրահանգիր cohort-ին Download և apply անել, հետևիր post-apply Inform-ին և return/failure rate-ին, ընդլայնիր ring-երով, և halt-on-failure արա known-good rollback image-ով — canary cohort նախ, երբեք ողջ fleet-ը միանգամից։ **TR-369 (USP)**-ն սա ընդհանրացնում է **controller/agent** architecture-ի՝ pluggable transport-ով (MQTT, WebSocket, STOMP, CoAP) և ավելի հարուստ data model ու operation set-ով, կառուցված scale-ի, NAT-friendliness-ի և non-HTTP device-ների համար. օպերացիոն կարգապահությունը — staged rollout, canary, halt-on-failure, rollback image — անփոփոխ է։

### Mediation / CDR խորը բաժին (dedup, normalization, ASN.1/TAP3)

Mediation-ը raw network record-ները դարձնում է մաքուր, billable, deduplicated, normalized record։ **Dedup․** network element-ները overlapping CDR են արձակում (նույն event-ը երկու node-ի կողմից տեսնված). dedup՝ stable record key-ով (element-id + sequence + timestamp window) կանխում է double-billing-ը — raw, undeduped feed rate անելը revenue bug է։ **Normalization․** միավորիր field format-ը, time zone-ը, unit-ը և semantics-ը heterogeneous vendor element-ների միջև, որ rating-ը մեկ schema տեսնի, և correlate արա partial record-ները (երկար session-ներ՝ file-երի միջև բաժանված) մեկ usage event-ի։ **ASN.1/TAP3․** roaming usage-ը operator-ների միջև փոխանակվում է **TAP3** record-ով, **ASN.1**-encoded. decode և validate արա TAP3 file-ը (և reject/RAP-return արա malformed-ները) մինչև roaming-ը rate անելը։ Միայն dedup + normalization + correlation-ից հետո record-ները հասնում են rating-ին․ **OCS** (Diameter Gy) real-time, balance-aware credit-control-ի համար, կամ **offline batch** postpaid CDR rating-ի համար։

### Lawful intercept խորը բաժին (օպերացիոն, gated)

Lawful intercept-ը target-ի communication-ի warrant-լիազորված handover-ն է authorized agency-ին, երկու stream-ով — **IRI** (intercept-related information / metadata․ ով, երբ, որտեղ) և **CC** (call content) — հանձնված mediation/handover function-ով standardized interface-ով (օր.՝ ETSI handover)։ **Skill-ի դերը վավերացված օրինական order-ի տակ կատարումն է՝ խիստ scope-ով և audit-ով, երբեք design-on-request չէ։** Operations․ (1) ընդունում է intercept միայն փաստաթղթավորված օրինական channel-ով՝ order-ը file-ում. (2) minimize է անում order-ի target-ին և time scope-ին. (3) պահում է audit trail և սերտ access control. (4) ուղղորդում է օրինականության, վավերականության կամ scope-ի ցանկացած հարց legal-ին և order տվող իշխանությանը։ Subscriber-ին tap/log/mirror/expose անելու հարցումը՝ առանց այդ վավերացված order-ի, ինչպես էլ ձևակերպվի, մերժվում է և ուղղորդվում legal-ին։ Սա inline hard gate-ն է. `red-team-gate.md`-ն միայն ընդլայնում է այն։

### Ստուգիր live, ոչ մաքուր parse

Config, որ parse է լինում, և lab, որ green է, անհրաժեշտ են, ոչ բավարար։ Change-ը done հայտարարելուց առաջ դիտիր running network-ը․ կարդա իրական route-count-ը expected post-state-ի դեմ, իրական Rx power-ը ազդակիր PON-ի վրա, իրական session count-ը BNG-ի վրա, իրական availability/latency/loss-ը SLA metric-ի վրա, իրական firmware-return rate-ը campaign-ի վրա։ Մաքուր parse-ը կամ green lab-ը «verified» համարելն այն ճանապարհն է, որով compile եղած change-ը միևնույն է region է գցում կամ bill է կրկնապատկում։
