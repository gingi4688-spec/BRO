# Operating Data Roles domain rubric

## English

Use this rubric before finalizing a routing tree, RACI/RAPID grid, handoff contract, operating map, or role-confusion postmortem. A score of 5 requires the mechanism, the evidence, and a checkable artifact — vocabulary alone scores 1.

| Dimension | 1 — weak | 3 — usable | 5 — senior |
|---|---|---|---|
| Routing precision | Role titles are listed; routed by seniority or convenience. | Owner is guessed from the symptom. | Symptom is classed via the lens cascade and maps to a role, the artifact it produces, one acceptance check, and an escalation path. |
| Role boundaries | Analyst / scientist / engineer blur; one person spans pipeline, meaning, and modeling. | Some boundary is named. | Descriptive, semantic, causal, pipeline, ML, and architecture duties are separated, and the analyst≠scientist≠engineer line is explicit. |
| RACI / RAPID quality | No Accountable, or "everyone owns quality." | RACI labels exist. | Exactly one Accountable per decision; steward (meaning/quality/policy) and owner (delivery/SLA) are both named; RACI vs RAPID is chosen correctly and the grid changes a real handoff. |
| Handoff contracts | Meeting notes only. | Some acceptance criteria. | Contract carries grain, SLA/freshness, schema-change policy, backfill, idempotency key, tests, owner, and escalation; the receiver accepts only on a passing real run. |
| Operating repair & boundary | Adds more meetings; imposes data-mesh vocabulary with no substrate; designs the architecture itself. | Adds a process step. | Repairs the missing artifact / decision right / monitoring signal; gates mesh vocabulary against maturity; routes any platform/contract/topology *design* to `data-architecture-leadership` with the steward named. |

## Հայերեն

Կիրառիր այս rubric-ը նախքան routing tree, RACI/RAPID grid, handoff contract, operating map կամ role-confusion postmortem վերջնականացնելը։ 5 միավորի համար պետք է mechanism, evidence և ստուգելի artifact — միայն vocabulary-ն 1 է ստանում։

| Չափանիշ | 1 — թույլ | 3 — կիրառելի | 5 — senior |
|---|---|---|---|
| Routing precision | Միայն role title-ներ են թվարկված. ուղղորդված seniority-ով կամ հարմարությամբ։ | Owner-ը գուշակված է symptom-ից։ | Symptom-ը class արված է lens cascade-ով և կապվում է role-ի, artifact-ի, որ արտադրում է, մեկ acceptance check-ի և escalation path-ի հետ։ |
| Role boundaries | Analyst / scientist / engineer խառնված. մեկ մարդ ընդգրկում է pipeline, meaning և modeling։ | Որոշ boundary կա։ | Descriptive, semantic, causal, pipeline, ML և architecture պարտականությունները բաժանված են, և analyst≠scientist≠engineer գիծը բացահայտ է։ |
| RACI / RAPID quality | Accountable չկա, կամ «բոլորը quality-ի owner են»։ | RACI label-ները կան։ | Ճիշտ մեկ Accountable ամեն որոշման. steward (meaning/quality/policy) և owner (delivery/SLA) երկուսն էլ անվանված. RACI ընդդեմ RAPID-ի ճիշտ է ընտրված, և grid-ը փոխում է իրական handoff։ |
| Handoff contracts | Միայն meeting note։ | Որոշ acceptance criteria։ | Contract-ը կրում է grain, SLA/freshness, schema-change policy, backfill, idempotency key, tests, owner և escalation. ստացողը ընդունում է միայն անցնող իրական run-ի վրա։ |
| Operating repair & boundary | Ավելացնում է meeting-ներ. պարտադրում է data-mesh vocabulary առանց substrate-ի. ինքն է architecture-ը դիզայն անում։ | Process step կա։ | Շտկում է բացակայող artifact-ը / decision right-ը / monitoring signal-ը. gate է անում mesh vocabulary-ն maturity-ի դեմ. ուղղորդում է ամեն platform/contract/topology *design* `data-architecture-leadership`-ին՝ steward-ը անվանված։ |
