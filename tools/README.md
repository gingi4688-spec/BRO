# tools/ — Super Bro scripts / Super Bro-ի script-եր

> **EN:** Real scripts that return exit codes — the **executors behind the Command Palette** (OD-4: Bro presents menu/preview/approval; scripts do the side-effects; hooks are the wall). Clean-build **Phase 0 ships ONLY** a minimal read-only bootstrap doctor. The full doctor/audit/drift/skill/spine suite **and** the structural hooks land in **Phase 2+**.
> **HY:** Real script-եր՝ exit-code վերադարձնող — **Command Palette-ի executor-ները** (OD-4: Bro-ն ներկայացնում է menu/preview/approval; script-երն անում են side-effect-ները; hook-երը պատն են)։ Մաքուր-build **Phase 0-ն բերում է ՄԻԱՅՆ** minimal read-only bootstrap doctor։ Լրիվ doctor/audit/drift/skill/spine + structural hook-երը՝ **Phase 2+**։

## Current scripts / ընթացիկ script-եր

### Phase 0 — bootstrap
- **`bro-doctor.ps1`** — read-only doctor. **Phase 0:** skeleton presence · `bro.manifest.json` validity + fields · **verify-only** authority (OD-3) · `_own` structure (no stray project content) · live spine at root (OD-6) + `RELEASES/` empty (OD-5). **Phase 1 (added):** Command Palette + library presence, library JSON validity + schema, read-only-backing resolution, and that **no critical command is live** in the clean build. Exit codes: `0`=GREEN · `1`=YELLOW · `2`=RED · `3`=CRITICAL. **Writes nothing.** / Read-only doctor — ոչինչ չի գրում։

### Phase 1 — Command Palette + Library
- **`bro-palette.ps1`** — Guided Command Palette runner (§6B / D10 / OD-4): **menu → preview → explicit `YES` → run**. Read-only commands (`HELP · SHOW REGISTRY · SHOW HEALTH · RUN DOCTOR · EXIT`) execute via **named, explicit dispatch** (no arbitrary execution); critical/future commands are **preview-wired but execution-gated** (refuse to run until their phase/system exists + Gev authority). Interactive menu (no args) or `-Command "<name>" [-Confirm YES]` non-interactively. / Palette runner՝ menu → preview → `YES` → run; read-only-ները live, critical-ները gated.
- **`bro-show-registry.ps1`** — read-only: prints `memory/_own/registry.json` (metadata only; empty in clean build). / read-only registry print.
- **`bro-show-health.ps1`** — read-only: prints the generated `memory/_own/health-dashboard.md` snapshot. / read-only health snapshot print.
- **`command-library.json`** — machine-readable catalog the palette reads (mirror of `_core/COMMAND_LIBRARY.md`, the human SSOT). / palette-ի machine catalog։

### Phase 2 — Enforcement + Evidence + full Doctor/Audit (the WALL, §11/D5/B5)
- **`hooks/forbidden-path-write-guard.ps1`** — PreToolUse (Write|Edit): blocks writes to another project's memory, `memory/supermemory/**`, `memory/_own/secrets/**`, or anything outside BRO_HOME. **R-1 refinement:** a narrow, **slug-keyed whitelist** allows THIS project's legitimate harness paths (`~/.claude/projects/<slug>/` auto-memory and `…\Temp\claude\<slug>\` scratchpad); another project's harness memory and every EP/DB/GAA/IP folder stay blocked. **Gate-2 exception:** a **registry-keyed** allowance for a **registered** project's `<project_path>\bro\` subtree ONLY (validated against the registry, status REGISTERED|INSTALLED) — never the project root, never `<project_path>\memory`, never an unregistered project. Registration (Gev-gated) is the approval. Registry source = `memory/_own/registry.json` (canonical); the `$env:BRO_REGISTRY_PATH` override is **test-only — honored ONLY when `$env:BRO_TEST_MODE=1`** (Beast Gate 4); in production a fake override is ignored. / forbidden-path write block + slug-keyed harness whitelist + registry-keyed `\bro\` exception + hardened test seam.
- **`hooks/log-append-only-guard.ps1`** — PreToolUse (Write|Edit): blocks Edit/Write on append-only evidence logs (use `bro-log.ps1`). Layered with the write-guard (defense-in-depth, C6). / evidence-log append-only.
- **`hooks/cross-memory-read-guard.ps1`** — PreToolUse (Read): **scope-aware** isolation. A Bro may read ONLY its own project's memory (scope from `memory_scope` in the local manifest; the `$env:BRO_SCOPE` override is **test-only — honored ONLY when `$env:BRO_TEST_MODE=1`**, Beast Gate 4). SuperBro (`own_only`) is blocked from reading ANY project's `\bro\memory` (it uses sealed mirrors); a Project Bro `X` may read `X\bro\memory` but is blocked from every other project's memory (B4/L8). / scope-aware cross-project read block.
- **`hooks/critical-command-gate.ps1`** — PreToolUse (Bash|PowerShell): blocks a real `git push` and actual execution of a critical SuperBro script (`bro-release/promote/register/install/update-spine`) unless `BRO_GEV_APPROVED=1` (push = Gev-gated, §8A). **R-1 refinement:** detection runs on a **scrubbed** command (heredoc bodies + quoted strings removed) and is **anchored to actual command tokens / `-File` execution**, so a critical word in a commit message, prose, comment, or a file-path argument (e.g. `git add tools/bro-register.ps1`) no longer false-blocks. / critical-command gate, anchored.
- **`hooks/preflight-printer.ps1`** — SessionStart: prints the per-session pre-flight banner (project · allowed memory · forbidden paths · spine version · critical-needs-Gev · cross-project OFF). / session pre-flight.
- **`bro-log.ps1`** — the ONLY sanctioned append-only evidence writer; **script-generated** timestamps + session_id (no fabrication). / append-only evidence writer.
- **`bro-audit.ps1`** — read-only audit suite (manifest · authority · `_own` boundary · drift · enforcement deliverables); flags only, never fixes. `-Log` appends one audit-log entry. F3 whitelist: filename-based `_own` check + GAAhex sealed-mirror whitelist. / read-only audit.
- **`bro-health.ps1`** — regenerates `memory/_own/health-dashboard.md` from doctor+audit (a generated snapshot, overwrite — not append-only). / health snapshot generator.
- **`bro-spine-check.ps1`** — read-only spine integrity (live spine at root OD-6 · key content · spine_version · RELEASES well-formed). / spine integrity.

### Beast hardening — project-scoped tooling
- **`bro-project-doctor.ps1`** — read-only, **fail-closed** project-scoped doctor: cross-checks an INSTALLED Project Bro against the registry + its pulled spine release (skeleton · manifest validity · project_id/memory_scope/authority/status/spine_version match · full spine hash verify (every payload file vs the pulled release manifest — count is read dynamically, not fixed) · memory/logs/health existence · no unexpected supermemory mirror). Unknown / missing / mismatched → **RED**. Reads metadata only — never the project's sealed memory content (B4/L8). `-RegistryPath` is an explicit test parameter (no env bypass). / fail-closed project doctor.
- **`bro-project-audit.ps1`** — read-only, **evidence-backed** project audit: project_id · project_path · registry status · manifest values · spine version · hash-verify result · memory-scope result · isolation posture · touched-path boundaries · known limitations, then reflects the project doctor's verdict. **REFUSES (exit 3)** if the manifest and registry disagree (project_id / scope / status) or the project is unknown. `-Log` appends an audit-log entry. Sealed memory content never read. / evidence-backed project audit, refuses on mismatch.

- **`bro-beast-check.ps1`** — the **whole-factory regression matrix**: one runner aggregating git state · SuperBro doctor/audit/spine-check/registry-check · project doctor + audit (EP) · release v1.0.0 verify · live guard regression (cross-project write/read BLOCK, in-home ALLOW, evidence-log edit BLOCK, push BLOCK, approved push ALLOW) · isolation proof · no-secret/pre-push dry check → single **GREEN/RED** verdict (exit 0/2). Guard tests run via `Start-Process` stdin and log block evidence to a temp file (test-mode `BRO_HOOKBLOCKS_PATH`, gated by `BRO_TEST_MODE=1`) so the canonical `hook-blocks.md` stays clean and the runner is idempotent. / factory-wide regression matrix.

### Phase 3 — Registry + Project Bro Template + Rollout Dry-Run (design/dry, NO install)
- **`bro-register.ps1`** — REGISTER PROJECT (**DRY default; gated real** = `-Execute -Yes BRO_GEV_APPROVED=1`): writes EXACTLY ONE metadata-only entry after a `_before` snapshot; refuses a path inside another project's memory or inside BRO_HOME (B4) and a duplicate `project_id`. **RETIRE mode** (`-Retire -ProjectId X`): flips status → `RETIRED` (metadata only; NO file deletion; instance left in place); refuses unknown/already-retired. / register + retire lifecycle.
- **`bro-install.ps1`** — INSTALL PROJECT BRO (**DRY default; gated real**): creates ONLY `<path>\bro\` (fresh empty sealed memory), pulls+verifies a release, stamps `spine_version`; NEVER touches `<path>\memory`. **ROLLBACK mode** (`-Rollback`): undoes a FAILED/partial install by removing `<path>\bro\` ONLY; **refuses if status is INSTALLED** (use `-Retire` first) or if the sealed memory grew beyond the fresh seed; never touches `<path>\memory` or the project root. / install + rollback lifecycle.
- **`bro-update-spine.ps1`** — UPDATE PROJECT BRO SPINE, **DRY-RUN only**: previews the pull→verify→stamp plan; executes nothing (the procedure itself is Phase 4). / DRY spine update.
- **`bro-registry-check.ps1`** — read-only registry validator (schema + empty + no cross-project path, B4). / read-only registry check.
- **`templates/project-bro/`** — the install copy-source skeleton (manifest+health templates with `<PLACEHOLDER>` tokens; empty `memory/ spine/ logs/`). Nothing here is an installed Bro. Full contract: `_core/PROJECT_BRO_TEMPLATE.md`. / install copy-source.

> **DRY default + gated real mode (Gate-3):** rollout commands default to **DRY preview** (execute nothing). **Real execution requires ALL three:** `-Execute` + `-Yes` + `BRO_GEV_APPROVED=1` (two layers — the critical-command-gate must let the command run, and the script itself checks the env approval). Real `bro-register` writes one metadata-only registry entry (after a `_before/registry-<ts>.json` snapshot, B4 cross-path refusal active). Real `bro-install` creates ONLY `<path>\bro\` (fresh empty sealed memory), pulls + verifies a release, stamps `spine_version`, and never touches `<path>\memory`. / Default DRY; real execution = `-Execute` + `-Yes` + `BRO_GEV_APPROVED=1`; metadata-only registry; install touches only `\bro\`.

### Automation — Daily Autopilot + Governance front door (FULL AUTO, push-by-token only)
> Gev's model: **everything automatic and off Gev — the ONLY thing reserved for him is the PUSH token.** These tools never ask Gev; they auto-handle blockers (auto-stash WIP) and commit locally, and push ONLY with `BRO_GEV_APPROVED=1`.
- **`bro-selfaudit.ps1`** — one-command self-doctor: runs **doctor + audit** (and beast on demand), **dirty-tree-aware**, and prints a single `OVERALL: GREEN/YELLOW/RED`. Backs the `RUN SELF-AUDIT` palette entry and the SessionStart front door. Read-only. / one-command self-doctor.
- **`bro-autopilot.ps1`** — the **daily brain** (runs at 11:00): **self-check FIRST, fail-CLOSED** — it dispatches only if the self-audit is GREEN/YELLOW; then dispatches each registered Project Bro **and Bro itself** to work its planned items, **commits locally, and NEVER pushes** (push = Gev-token only). Skips already-done work; does not wait for Gev. / daily self-check → dispatch → commit-local (never push).
- **`bro-dispatch.ps1`** — **bounded** headless dispatch of one Project Bro: `claude -p --permission-mode acceptEdits` + an explicit allow/deny list (**NEVER `bypassPermissions`**). **Auto-stashes Gev's WIP and restores it byte-identical**, structurally **disables push** for the duration (pushurl sentinel, restored after), and always checks back out to the origin branch. / bounded dispatch, WIP-safe, push-disabled.
- **`bro-push.ps1`** — the **one push path for every bro** (Gev: "all bros push with my token"): auto-stash WIP → `git push <remote> <branch>` (**the project's pre-push quality gate still runs and still protects**) → restore WIP. Gev-token-gated; `-NoVerify -Reason '<why>'` skips the gate ONLY with a recorded justification. / structural push-by-token, WIP-safe.
- **`bro-schedule.ps1`** — registers/updates the **daily 11:00 Windows Scheduled Task** that runs the autopilot heartbeat (no execution-time limit; StartWhenAvailable; logs to gitignored `logs/`). Backs the `SCHEDULE SELF-AUDIT` palette entry. / daily scheduled-task registrar.
- **`bro-cross-grant.ps1`** — **L8-G**: records a Gev-gated, **time-boxed, READ-only** cross-project grant in an append-only grant log; never opens a write path and never copies sealed-memory content. / L8-G read-only cross-grant.
- **`bro-new-project.ps1`** — the **project factory** (DRY default; gated real): scaffolds a new project folder + governed Bro install + `CLAUDE.md` (L8) + fresh sealed brain + intake, so Gev opens a ready-to-work window. / new-project factory.

### Recovery / Rollback doctrine (topist) / Վերականգնում ու rollback (topist)
> **EN — Recovery is snapshot-restore + forward-fix; NEVER history rewrite. Every recovery path is evidence-backed and (for writes) Gev-gated.**
> | Failure | Recovery path | Guard |
> |---|---|---|
> | **Failed / partial install** | `bro-install -Rollback -ProjectId X -ProjectPath <abs>` — removes `<path>\bro\` ONLY | refuses if status INSTALLED (RETIRE first) or sealed memory grew beyond seed; never touches `<path>\memory` |
> | **Bad registry write** | restore the pre-op snapshot `_before/registry-<ts>.json` (every real register/retire snapshots first) | metadata only; B4 still enforced on restore |
> | **Corrupted / tampered release** | `bro-spine-verify` REJECTS (BLACK); re-pull from a known-good release — **never edit a payload in place** | hash + rollup mismatch = reject, no blind copy |
> | **Mistaken boundary / wrong change** | **forward-fix** = a new commit that corrects it (as the L10 boundary correction did) | **NEVER** `git reset`/rebase/force-push to rewrite published history |
> | **Dirty tree before a release/seal** | **STOP** — `bro-doctor` flags it ([10]); resolve/commit first | `-Strict` makes a dirty tree RED |
> | **Active Project Bro to decommission** | `bro-register -Retire -ProjectId X` — status → RETIRED (metadata only) | NO file deletion; instance left in place |
>
> **No force-push** except a **separate, explicit Gev FORCE authority** (push itself is already Gev-gated, §8A). **Retire ≠ rollback:** an active (INSTALLED) Bro is RETIRED (metadata), never deleted; rollback is only for a failed/fresh install.
> **HY — Վերականգնումը snapshot-restore + forward-fix է. ԵՐԲԵՔ history rewrite։** Failed install → `bro-install -Rollback` (միայն `\bro\`); bad registry → restore `_before/registry-<ts>.json`; corrupted release → verify REJECT + re-pull (ոչ in-place edit); սխալ boundary → **forward-fix** (նոր commit, ոչ force-push); dirty tree → **STOP** (doctor); active Bro decommission → `-Retire` (metadata, ոչ ջնջում)։ Force-push = միայն առանձին բացահայտ Gev FORCE authority-ով։
>
